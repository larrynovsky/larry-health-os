# How-to: обновить сезонную таблицу (пакет региона, ключ `seasonal`)

Таблица месяц → {fruits, vegetables, seafood} — данные региона дома в `private/region.yaml`
(ключ `seasonal`), читает её `seasonal_produce.py` через `region_pack`. Сезоны стабильны →
ре-скрап нечастый, руками по источникам. Утверждённые источники для текущего региона записаны
в самом пакете (ключ `sources`) — они называют регион и потому в публичной документации не стоят.

## Когда
- Заметил ошибку в сезоне продукта.
- Хочешь уточнить/расширить список (новый продукт, другой источник).

## Какие источники годятся
- **Фрукты/овощи:** официальный гастрономический календарь региона + местные сезонные блоги.
- **Рыба и морепродукты:** сезонные справочники для выбранного региона и данные поставщиков;
  учитывай доступность привозной продукции, а не только местный улов.

## Шаги
1. Открой источник, выпиши сезонные диапазоны продуктов.
2. Разложи по месяцам в `seasonal:` пакета (интерполяция диапазона — это ОК, помесячно — отображение).
   Названия — по-русски, как остальные (для совпадения с `FOOD_BENEFITS`/`_SEAFOOD_BENEFITS`).
3. Региональный каталог хранится в `food_catalog:` того же пакета: разделы `produce` и `seafood`,
   алиас продукта → `{tag, why: {ru, en}, label: {ru, en}}`. Это полный каталог установки,
   заменяющий общий европейский набор из `food_genome`, а не дополнение к нему.
   Добавь НОВОМУ продукту тег пользы, причины и подписи на обоих языках; без записи он не попадёт в бриф.
4. `pytest tests/unit/test_seasonal_produce.py tests/unit/test_food_genome.py -q` → all-pass.
5. Коммить с MacBook.

## Мины
- Продукт без записи в `FOOD_BENEFITS`/`_SEAFOOD_BENEFITS` → молча выпадает из брифа (не ошибка,
  просто нет пользы-обоснования). Проверяй, что новый продукт добавлен в обе стороны.
- Ранг в брифе: фрукты(0) > овощи(1) > морепродукты(2), внутри — фолат-boosted вперёд.
- Кулдаун per-продукт (semantic_key `food:seasonal:<tag>:<продукт>`) даёт ротацию ~месяц.
