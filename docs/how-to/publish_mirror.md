# Как обновить открытый репозиторий и принять правку оттуда

Рабочий репозиторий закрыт вместе с историей. Открытый репозиторий
`github.com/larrynovsky/larry-health-os` — зеркало его публичной зоны: всё, что не перечислено
в `publication_zones.yaml`. Каждая выгрузка — один коммит «Export of <sha>».

## Выгрузить

```bash
cd ~/health_scripts
python3 scripts/public_mirror.py            # собрать и закоммитить в клон зеркала
python3 scripts/public_mirror.py --push     # то же и отправить на GitHub
```

Собирается закоммиченное состояние `main`: незакоммиченное и приватное не уезжают, файлы,
удалённые в работе, удаляются и в зеркале. Клон зеркала лежит в `~/.public_mirror/larry-health-os`.

`--push` отказывает, пока не прочитан каждый публичный файл, изменённый после отметки прочитанного
(`plans/publication_read.txt` в закрытой части): в прозе проекта легко остаётся «замер на живых данных». Порядок:

```bash
python3 scripts/public_mirror.py --unread           # что прочитать: изменённые публичные файлы
python3 scripts/public_mirror.py --mark-read main   # после чтения и правок; закоммитьте отметку
```

Отметка судится по закоммиченной версии в выгружаемом коммите, а не по файлу на диске: незакоммиченная отметка пуш не откроет.

Перед `--push` сделайте ещё контрольный поиск по словам своей истории болезни: видам лечения,
процедурам, местам. Страж и словарь `private/pii_terms.yaml` ловят известные слова, но не
структуру. 29.09 тестовая фикстура содержала личные медицинские сведения под
выдуманными названиями: перепись дала 0, двадцать один читатель её пропустил (урок C-93).
Каждое совпадение судите по структуре — похоже ли это на вашу историю, — а не по тому,
написано ли рядом «реальный» или «замер».

```bash
git grep -n -i -E "химио|лучев|облуч|операц|рецидив|chemo|radiat|surgery|relapse" main -- tests/
```

## Принять правку из открытого репозитория

Правка извне приходит пулл-реквестом в открытый репозиторий. Сливать его там нельзя:
следующая выгрузка затрёт всё, чего нет в рабочем репозитории. Путь один — через рабочий:

```bash
cd ~/health_scripts
scripts/thread_start.sh pr-<номер>
cd ~/.worktrees/health_scripts/pr-<номер>
gh pr diff <номер> --repo larrynovsky/larry-health-os | git apply --3way
```

Дальше как с любой своей правкой: тесты, коммит с упоминанием автора
(`Co-Authored-By: имя <почта>`), закрытие нити. После выгрузки закройте пулл-реквест на GitHub
со ссылкой на коммит «Export of …», в котором правка уехала.

## Если что-то пошло не так

| Что видно | Что сделать |
|---|---|
| «зеркало уже совпадает» | Выгружать нечего: в `main` нет новых публичных изменений |
| «⛔ … не прочитаны после отметки» | Прочитайте файлы из `--unread`, уберите следы живых данных, закоммитьте, поставьте `--mark-read` |
| `git apply` не накладывает правку | Автор писал её к старой выгрузке. Попросите его обновить ветку или перенесите руками |
| В зеркале оказался файл, которого там быть не должно | Добавьте его путь в `publication_zones.yaml` с причиной, закоммитьте и выгрузите снова. Из истории открытого репозитория он при этом не исчезнет — если это личные данные, удалите репозиторий и выгрузите заново |
