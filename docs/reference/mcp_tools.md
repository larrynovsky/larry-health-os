# Инструменты MCP Health OS

Что сервер MCP (`health_mcp.py`, инструменты — `mcp_tools.py`) отдаёт облачным помощникам.
Подключение — [how-to](../how-to/connect_cloud_assistants.md), замысел — [explanation](../explanation/mcp_gateway.md).

## Общее для всех инструментов

| Свойство | Как устроено |
|---|---|
| Запись | Нет. Все инструменты только читают, через существующие функции `*_db` |
| Чьи данные | Каталог данных процесса (`HEALTH_DATA_DIR`); аргумента «тенант» нет |
| Начало ответа | `Источник: Health OS — <что>. Выдано <ГГГГ-ММ-ДД>.`, затем JSON |
| Пустота | `нет данных: <что>. Не достраивай значения — скажи, что в Health OS этого нет.` |
| Неверный аргумент | `неверный аргумент: <что не так>`, флаг ошибки MCP |
| Сбой чтения | `Health OS не смог прочитать данные — внутренняя ошибка, данных в ответе нет`, без трассы |
| Личное | Имя, дата рождения, идентификаторы вырезаны словарём (`[скрыто]`); путь к бланку не отдаётся |

## Инструменты

| Имя | Аргументы | Что возвращает |
|---|---|---|
| `ping` | — | «Health OS на связи.» Данных о здоровье нет |
| `health_brief` | — | Тот же бриф о человеке, что бот получает перед каждым ответом: текущая вера, возраст, диагноз и статус, лечение с датами, действующие проблемы, свежие анализы с флагами, личная норма ВСР. Помощнику велено начинать с него |
| `nutrition_frame` | — | Рамка питания, выведенная кодом по курируемым правилам: энергия, белок, микроэлементы, ограничения, причина каждого пункта. Отдельно — правила консилиума со статусом shadow, каждое с пометкой «НЕ одобрено владельцем» |
| `lab_tests` | — | Список анализов: имя, дата последнего результата, число результатов (за 20 лет) |
| `lab_results` | `test_name` (строка ≤ 100), `days` (целое, по умолчанию 1825, потолок 7300) | Ряд одного анализа: дата забора, значение, единица, референс бланка |
| `day_metrics` | `date` (`ГГГГ-ММ-ДД`) | Показатели приборов за день в том виде, как их хранит Health OS |
| `problems` | `status`: `current` (по умолчанию — действующие в любом статусе наблюдения), `resolved`, `all` | Список проблем медкарты: название, статус, даты, краткое описание |
| `facts` | — | Долгие факты памяти: ключ, значение, с какой даты. Разовые (transient) не отдаются |

## `lab_results`: вещество, а не название

Сначала ряд собирается по веществу (LOINC): разные написания одного анализа и разные шкалы
сводятся в одну. Ответ: `by` (как собран ряд), `names_merged` (какие названия сведены), `points`
(до 500 точек), `not_merged` (строки, которые свести не удалось). Если вещество не найдено, ряд
собирается по точному названию, и ответ говорит: «точное название, БЕЗ сведения веществ … ряд
может быть неполным».

Граница: референс отдаётся так, как он лежит в базе. Если норма записана не в той шкале, что
значение, помощник увидит это расхождение как есть.
