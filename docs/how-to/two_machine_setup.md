# Как добавить вторую машину для разработки

> **Тип документа:** How-to (Diátaxis). Для тех, кто уже прошёл
> [первую установку](../tutorials/first_install.md) на основной машине и хочет писать код на
> другой (ноутбуке), а работать система будет по-прежнему на основной.
> Почему устроено так: [git_architecture](../explanation/git_architecture.md).

**Правило, которое держит всё остальное:** данные и работающая система живут на ОДНОЙ машине —
основной. Вторая машина пишет код и коммитит; коммит сам уезжает на основную и там
применяется. Базы на второй машине нет и быть не должно.

## 1. Назовите основную машину

В `private/infra.yaml` на обеих машинах один и тот же `primary_host` — имя основной машины
(как его печатает `hostname`). По нему код решает, где ему разрешено писать в базу
(`infra_config.is_primary`), а установщик хуков — какие хуки ставить.

## 2. Разрешите основной машине принимать push в рабочее дерево

На основной машине, в каталоге репозитория:

```bash
git config receive.denyCurrentBranch updateInstead
```

Без этого push в ветку, которая сейчас открыта, git отклонит.

## 3. Склонируйте репозиторий на вторую машину

```bash
git clone <пользователь>@<основная>:health_scripts ~/health_scripts
cd ~/health_scripts
git remote rename origin studio
```

Имя remote `studio` не случайно: хук после коммита отправляет код именно туда, и адрес
основной машины он берёт из этого remote, второй копии адреса нет.

## 4. Подготовьте приватный словарь на второй машине

Клонирование не переносит `private/pii_terms.yaml`: он исключён из публичного экспорта
и из git в установке, созданной установщиком. До первого коммита добавьте
`/private/pii_terms.yaml` в локальные исключения git этой копии, затем перенесите словарь
с основной машины по приватному каналу (например, SSH). Не включайте его в коммиты,
issue или сообщения чата; ограничьте права файла до `600`.

Если переносить пока нечего, создайте пустой словарь. Из корня репозитория:

```bash
printf '%s\n' '/private/pii_terms.yaml' >> "$(git rev-parse --git-path info/exclude)"
mkdir -p private
test -e private/pii_terms.yaml || printf 'literals: {}\npatterns: {}\n' > private/pii_terms.yaml
chmod 600 private/pii_terms.yaml
```

`pii_census.py` отказывает в коммите, если файла нет. Пустые словари выше он принимает,
но тогда ему нечем обнаруживать личные литералы и шаблоны. Когда появится заполненный
словарь, перенесите его либо ведите собственные приватные записи. Файл нулевой длины
не является корректным пустым словарём.

## 5. Поставьте хуки на обеих машинах

На каждой машине, из главной копии репозитория (не из дерева задачи):

```bash
scripts/install_hooks.sh
```

Скрипт сам видит, где он запущен. На основной ставит хук приёма push, который после каждого
push переустанавливает хуки из репозитория. На второй — проверки перед коммитом и хук после
коммита: `git push studio main` и перезапуск бота и дашборда на основной.

## 6. Проверьте

Сделайте на второй машине пустую правку документа и закоммитьте. Результат, которого ждём:

- в выводе коммита — строка о push на основную;
- на основной `git log -1` показывает этот коммит.

Если коммит остался только на второй машине — проверьте `git remote -v` (шаг 3) и
`receive.denyCurrentBranch` (шаг 2).

## Тесты на второй машине

Базы здесь нет, поэтому тесты сами уводят данные во временный каталог (`tests/conftest.py`).
Полный прогон — на основной: [run_tests](run_tests.md). Параллельная работа нескольких задач —
в своих деревьях: [thread_worktree](thread_worktree.md).
