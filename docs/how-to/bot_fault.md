# Что-то пошло не так — как сообщить разработчику

> **Жанр (Diátaxis): how-to.** Для того, кто сам поставил систему по
> [уроку установки](../tutorials/first_install.md) ([English](../tutorials/first_install.en.md)):
> бот ответил «Не получилось ответить: сбой внутри системы…» с кодом, не прислал утренний отчёт
> или не отреагировал на кнопку.

Бот при этом продолжает работать, спешить некуда.

## 1. Напишите боту /bug

Бот спросит, что случилось, — выберите кнопку, которая ближе всего: «Не пришёл отчёт», «Бот не
ответил на кнопку или команду», «Анализ не распознался» или «Другое». Затем он покажет, что именно
уйдёт разработчику, и спросит «Отправить?».

Уходят только: версия и система, выбранная кнопка, тип и место сбоев за неделю (например,
`KeyError в labs_db.py`), что подключено (да/нет) и названия последних сообщений бота — без их
текста. Не уходят никогда: тексты сообщений, ваши данные и анализы, ключи. Полный список —
[что уходит в отчёт](../reference/bug_report_fields.md).

Ответ «Доставлено, номер R-…» значит, что отчёт у разработчика. «Сейчас нет связи» — отчёт
сохранён, бот отправит его сам. «В этой сборке отправка не настроена» — вы собрали образ сами, а не
скачали выпуск; тогда пункт 3.

## 2. Если бот не отвечает вовсе

Из каталога установки (по уроку — `~/health-docker`):

```bash
cd ~/health-docker
docker compose run --rm cron python3 -m bug_outbox
```

Команда покажет тот же отчёт и спросит, отправлять ли его.

## 3. Отчёт на GitHub вместо бота

Если у вас есть аккаунт GitHub и вы хотите обсудить сбой открыто, напечатайте тот же отчёт и
вставьте его в [новую задачу](https://github.com/larrynovsky/larry-health-os/issues/new):

```bash
docker compose run --rm cron python3 -m bug_outbox --print
```

Не вставляйте в задачу строки из журналов `faults.jsonl` и `bot_err.log`: в тексте ошибки бывает то,
что вы писали боту, или значение анализа. Отчёт из команды выше их не содержит.

Если у вас есть свой ИИ-ассистент с доступом к установке (например, Claude), попросите его
разобрать сбой по коду и оформить задачу: что делали, что увидели, где в коде причина. Такая задача
помогает больше короткого отчёта. Перед отправкой прочитайте её сами и уберите из неё ваши данные,
значения анализов и строки журналов — задача на GitHub видна всем.

## Частые причины, которые можно поправить самому

| Бот или отчёт говорит | Что это | Что сделать |
|---|---|---|
| `authentication_error`, `credit balance` в разделе сбоев | ключ поставщика моделей неверный или на счёте нет денег | шаг 4 урока: проверьте ключ и баланс, затем `docker compose restart bot` |
| бот молчит, в журнале `InvalidToken` | неверный токен Telegram | шаг 6 урока |
| `Read-only file system` | версия бота старая | обновитесь — раздел «Как обновиться» урока |

## Почему бот не пишет подробности прямо в чат

Текст ошибки может содержать служебные адреса, куски ключей и ваши данные, а сообщения в Telegram
часто пересылают. Поэтому в чат уходит только короткий код, а разработчику — отчёт, собранный из
полей, в которых личного быть не может.
