# Как добавить человека

Одна установка может вести нескольких людей — например, семью. У каждого своя база, свои
секреты, свой Telegram-бот и свои фоновые службы. Код общий. Этот рецепт заводит второго
(третьего…) человека на уже работающей основной машине.

Зачем так устроено и где граница изоляции — [multitenancy](../explanation/multitenancy.md)
([English](../explanation/multitenancy.en.md)).

## Перед началом

- Основная установка уже работает ([первая установка](../tutorials/first_install.md),
  [English](../tutorials/first_install.en.md)).
- Выберите имя человека: латиница в нижнем регистре, цифры, `_` (например, `anna`). Оно
  станет частью путей: `~/health_anna`, `~/.health_secrets_anna`.
- Узнайте его часовой пояс (IANA, например `Europe/Berlin`): утренняя сводка приходит
  по нему.
- Выберите свободный порт дашборда: `8001` занят основной установкой, `8002` — первым
  добавленным человеком, и так далее.

## 1. Пробный прогон установщика

```bash
cd ~/health_scripts
python3 scripts/install.py --tenant anna --tz Europe/Berlin --dashboard-port 8003
```

Установщик печатает, что создаст, и ничего не пишет.

## 2. Установка

```bash
python3 scripts/install.py --tenant anna --tz Europe/Berlin --dashboard-port 8003 --apply --launchd
```

Создаются `~/health_anna/data/health.db` (пустая база, права 600), каталог секретов
`~/.health_secrets_anna` (права 700) и плисты служб в `build/launchd/anna/`. Установщик
называет службы, которые человеку пока не ставятся, и почему.

## 3. Секреты человека

Положите в `~/.health_secrets_anna/` по файлу на секрет, значение — единственной строкой:

| Файл | Что это | Обязателен |
|---|---|---|
| `telegram_token` | токен ОТДЕЛЬНОГО бота этого человека (создаётся у @BotFather) | да |
| `telegram_chat_id` | id чата человека с его ботом | да |
| `oura_token` | личный токен Oura | если есть кольцо |
| `google_calendar_account`, `google_calendar_token.json` | вход в его календарь | если нужен календарь |
| `hae_ingest_token`, `location_ingest_token` | вход с его телефона | если шлёт данные с телефона |

Ключ модели (`anthropic_key`) и почтовые настройки общие для всей установки — они
остаются только у основной. Полный перечень и чей каждый секрет:
`SECRET_SCOPE` в `secrets_paths.py`.

Без своего каталога секретов процесс человека откажется стартовать, а не возьмёт секреты
основной установки — так задумано.

## 4. Потребуйте явного выбора человека

Установщик задаёт пути служб человека, но не включает `HEALTH_MULTITENANT`.
Без этого флага процесс на основной машине без `HEALTH_DATA_DIR` берёт каталог данных
основной установки. Включите предохранитель для всех людей, включая основного:

- Для ручных команд выполните в терминале и добавьте в файл запуска своей оболочки:

```bash
export HEALTH_MULTITENANT=1
```

С каждой командой передавайте `HEALTH_DATA_DIR` и `HEALTH_SECRETS_DIR` нужного человека;
не задавайте пути одного человека глобальным умолчанием для всех команд.

- Для launchd добавьте эту запись внутрь словаря `EnvironmentVariables` каждого используемого
  плиста — и основной установки, и добавленных людей:

```xml
<key>HEALTH_MULTITENANT</key>
<string>1</string>
```

Проверьте, что в каждом плисте явно указаны `HEALTH_DATA_DIR` нужного человека (абсолютный
путь к `health` или `health_anna`, не к вложенному `data/`) и каталог его секретов.
Один `export` в терминале не настраивает службы launchd. Добавляйте запись в собранные
плисты перед копированием; повторяйте после каждого запуска установщика с `--launchd`,
который перезаписывает плисты. Уже загруженные службы выгрузите через `launchctl bootout`,
затем скопируйте и загрузите обновлённые плисты. Любое непустое значение флага, включая `0`,
включает предохранитель.

## 5. Загрузка служб

```bash
cp build/launchd/anna/*.plist ~/Library/LaunchAgents/
for p in build/launchd/anna/*.plist; do
  launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/$(basename "$p")
done
launchctl list | grep '\.anna$'
```

Метки служб оканчиваются на `.anna` и не пересекаются со службами основной установки.

## 6. Знакомство

Человек пишет своему боту `/start`. Первый вопрос — язык (русский или английский),
дальше короткое знакомство. После него приходит первая утренняя сводка.

## 7. Проверка

- `launchctl list | grep '\.anna$'` — службы загружены, у бота есть PID.
- Утром ночная проверка целостности идёт и по данным человека. Если она что-то найдёт,
  сообщение придёт **оператору** (владельцу основной установки), а не человеку: только
  имена проверок, без значений из его данных. Вердикт лежит в `~/health_anna/logs/`.
- Датчик «след одного человека в базе другого» проверяет всех людей установки.

## Какие службы получает человек

Список — `templates/launchd/tenant_services.yaml`. Человек получает все службы с пометкой
`ready`: бот, дашборд, календарь, Oura, приём документов, литературу, конституции,
опросники, консилиум, продольный анализ, баллы PGS, напоминания и ночную проверку.

Не получает службы с пометкой `excluded` — они не нужны ему по замыслу:

- разбор находок ночной проверки: находки по данным человека приходят оператору;
- старый приём документов из папки iCloud основной установки: документы человека
  принимает `lab-intake`;
- одноразовый эксперимент, который уже отработал.

Пометка `blocked: <причина>` означает, что у службы появился общий с другим человеком файл
и копия затирала бы чужой результат. Установщик такую службу не ставит, пока это не
исправлено.

## Уже добавленный человек, заведённый руками

Если плисты человека когда-то написаны вручную, установщик их заменит. Повторите шаг 2 с
тем же именем, портом и поясом: каталоги и база останутся как есть («есть, не трогаю»),
плисты соберутся заново. Затем выгрузите старые плисты человека (`launchctl bootout`) и
повторите настройку предохранителя из шага 4 и загрузите новые плисты, как в шаге 5.

## Пределы

- Файлы машины не разделены между людьми: бот одного человека может прочитать файл,
  путь к которому ему прислали, даже если это файл другого. Изоляция стоит на данных и
  секретах, а не на файловой системе (люди одной машины доверяют друг другу).
- Общий еженедельный дайджест уходит, только когда боты всех людей дали согласие. Если
  бот одного человека упал, дайджест ждёт всех.
