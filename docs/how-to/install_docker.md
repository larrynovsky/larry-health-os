# Как поставить систему в Докере

Справочный рецепт установки в контейнерах со СВОЕЙ сборкой образа — на Маке с Colima, на Linux,
на любой машине с Docker. Своя сборка нужна, когда готового образа мало: документы на языке,
которого нет в распознавании (готовый образ знает английский и русский), или свои правки кода.
Здесь же варианты, которых нет в уроке: свой каталог секретов, отдельный контекст Докера.

Обычная первая установка — из готового образа, без клона и сборки:
[первая установка](../tutorials/first_install.md) ([English](../tutorials/first_install.en.md)).

## Перед началом

- Docker Engine с плагинами `compose` и `buildx`. На Маке: `brew install colima docker
  docker-compose docker-buildx`, затем `colima start --profile health --cpu 2 --memory 4
  --disk 20 --activate=false`. Размеры Colima запоминает с первого старта. `--activate=false`
  оставляет текущий контекст Докера на месте: иначе другие проекты на этом Маке, которые
  не указывают контекст явно, начнут ходить в эту виртуальную машину. Команды этой страницы
  тогда пишите с `docker --context colima-health …`. Чтобы профиль поднимался сам после
  перезагрузки, шаг 1 кладёт агент в `build/docker/host/com.larry.health.colima.plist`:
  скопируйте его в `~/Library/LaunchAgents` и выполните `launchctl bootstrap gui/$(id -u) <плист>`.
- Клон репозитория и Python 3.9 или новее на машине, где собираете (нужен только установщику).
- Часовой пояс человека (IANA, например `Europe/Berlin`): утренняя сводка приходит по нему.
- Каталог секретов (права 700) — как в [первой установке](../tutorials/first_install.md) ([English](../tutorials/first_install.en.md)):
  - `telegram_chat_id` и `telegram_token` — без них не поднимется бот (остальные службы поднимутся);
  - `anthropic_key` — без него не пишутся отчёты.

## 1. Собрать расписание и список исключений образа

Из корня клона:

```bash
cd health_scripts
python3 scripts/install.py --docker --tz Europe/Berlin
```

Строка итога: `cron 25, service 3, env 1, host 4, none 3 (всего 36)`. В `build/docker/`
появятся `compose.yaml` и `.env`, в корне — `.dockerignore`. Всё это генерируется; руками не правят.

## 2. Собрать образ

Оттуда же, из корня клона:

```bash
docker buildx build --load -f docker/Dockerfile -t health-os:local .
```

Первая сборка идёт минуты (на arm64 дольше: одна библиотека собирается из исходников); повторная —
секунды, из кэша. Тег `health-os:local` перезаписывается при каждой сборке. Сборка проверяет
контрольную сумму планировщика и совместимость пакетов (`pip check`); упала — дальше не идите.

Языки распознавания документов задаются при сборке, по умолчанию `eng rus`. Коды — трёхбуквенные,
как у движка распознавания Tesseract: `deu` немецкий, `ell` греческий, `fra` французский
([полный список](https://tesseract-ocr.github.io/tessdoc/Data-Files-in-different-versions.html)):

```bash
docker buildx build --load -f docker/Dockerfile -t health-os:local \
  --build-arg OCR_LANGS="eng rus deu" .
```

При каждом обновлении собирайте с тем же `--build-arg`, иначе новый образ соберётся без
вашего языка. Обновление своей сборки: `git pull`, затем шаги 1–3 заново; база и секреты
остаются в томах и в каталоге секретов.

## 3. Запустить

Всё ещё из корня клона — скопировать собранное в каталог запуска и перейти туда. **Все дальнейшие
команды — из каталога запуска.**

```bash
mkdir -p ~/health-docker && cp build/docker/compose.yaml build/docker/.env ~/health-docker/
cd ~/health-docker
HEALTH_SECRETS_HOST_DIR=/путь/к/секретам docker compose up -d
docker compose ps
```

Ожидается четыре службы: `bot`, `dashboard`, `lab-intake`, `cron`, в колонке STATUS — `Up …`
(`restarting` у `bot` — см. ниже). Службы стартуют после того, как `cron` создал базу; первые секунды
`cron` может быть `health: starting`.
Дашборд — на `http://127.0.0.1:8001/`, **только** на этой машине: порт опубликован на
loopback намеренно, у дашборда нет пароля.

## 4. Проверить, что система жива

```bash
docker compose exec cron python3 -c "import daemon_liveness as d; print(d.find_down_daemons())"
```

`[]` через пару минут после старта — все постоянные службы отмечаются. Строка «пульса нет
ни разу» у `bot` — бот не поднялся. Логи служб пишутся в файлы, а не в `docker compose logs`:

```bash
docker compose exec cron sh -c 'tail -n 20 /app/logs/bot_err.log'
```

Чаще всего там — не найден `telegram_chat_id` или `telegram_token` в каталоге секретов.

## Что нормально видеть при первом старте

- «пороги лаб-трендов не посеяны: нет снимка EFLM» и «лаб-пороги safety_net не посеяны» — снимки
  справочников не входят в образ по лицензии; система работает на резерве.
- «Нет действующего Google Calendar токена» — синхронизация календаря в контейнере необязательна;
  без неё календарь просто не подтягивается.
- В ночной проверке первых дней — «данных нет» и «не судимо в контейнере»: установка пустая, а
  предмет части проверок (git, приватные документы) в образ не входит.

## Если что-то пошло не так

- **`cron` перезапускается или не становится здоровым** — `docker compose logs cron`: вывод самого
  планировщика и установщика (логи задач — в `/app/logs`, как выше). Чаще всего неверный `--tz`.
- **Нужен доступ к дашборду с телефона** — не публикуйте порт на все интерфейсы. Используйте
  `tailscale serve --https=8443 http://127.0.0.1:8001` на хосте: доступ только из вашей
  частной сети, с сертификатом.
- **Напоминания на телефон** — необязательная служба: положите `caldav.json`
  (`{"url", "username", "password"}`) в каталог секретов; без него задачи видны в боте. Телефон
  забирает задачи по своему расписанию («Выборка данных»), не мгновенно.
