# Тест-промт: strand-fix генома + вынос хардкода из промптов (2026-06-18)

Промт для тестировщика/агента: проверить две связанные работы. Цель — не «прогнать
green», а **попытаться сломать**: найти места, где данные пациента/клинические
величины могли утечь обратно в промпт, где резолюция strand даёт ложный
wildtype/carrier, и где degraded-режим падает вместо нейтрального маркера.

Среда: тесты гонять на **Studio** (`ssh <studio_ssh>`, scipy в venv).
На MacBook часть integration падает с `ModuleNotFoundError: scipy` — это окружение, не баг.

## Часть A. Геном (strand-aware effect_allele)

### Что проверяем
`effect_allele` заполняется только при однозначной strand-резолюции; палиндромы/
мультиаллели/инделы → NULL by design; носители идут первыми, непроверяемые ограничены.

### Автотесты (есть — расширить)
- `tests/unit/test_effect_allele_resolve.py` — добавить кейсы: gt с нижним регистром,
  `alt` длиной >1 (индел), ref==alt, генотип `0/0`-стиль.
- `tests/integration/test_effect_allele_backfill.py` — добавить: повторный backfill
  после ручного UPDATE significance НЕ меняет effect_allele; источник `dbsnp_vcf`
  fallback когда clinvar пуст.
- **Property (добавить):** для случайных (gt, ref, alt) — если `resolve` вернул
  не-None, то `_zygosity` не объявляет носителя там, где ни один аллель генотипа
  (ни на одном strand) не равен alt. Инвариант «не выдумывать носителя».

### Charter (человек, оракул — внешний)
1. Взять 10 случайных `resolved`-носителей из прода, сверить зиготность с dbSNP/SNPedia
   по rsid+генотипу. Пример формы сверки (генотип выдуман): `rsNNNN` = AG → hetero.
2. Взять 5 `palindromic` (любые из выборки прода) — убедиться, что остаются NULL,
   а не угаданы.
3. Открыть реальный геном-блок (`genome_context.build_genetic_context_block`) — носители
   первыми? непроверяемые свёрнуты «… и ещё N»? verified wildtype — одной строкой?
4. **Попытка сломать:** найти вариант, где `clinvar.alt` ≠ `vcf.alt` (strand-конфликт) —
   убедиться, что backfill оставил NULL (`source_conflict`/`genotype_mismatch`), а не записал случайный.

### Мониторинг
`integrity_tests.check_effect_allele_coverage` — WARN при null_status>200 или resolved<30%.
Проверить: ручной UPDATE 300 строк в NULL → утренний триаж даёт WARN.

## Часть B. Вынос хардкода из промптов

### Что проверяем
В промптах нет данных/клинических литералов; профиль приходит из БД в рантайме;
геном — из `genome_context`; degraded-режим не падает.

### Автотесты (есть — расширить)
- `tests/unit/test_prompts_no_hardcode.py` — guardrail. Добавить запрещённые: имена
  врачей, города проживания, конкретные даты визитов, дозы препаратов (`мг/м²`).
- `tests/integration/test_patient_context.py` — добавить: брифа нет генома и порогов;
  биом-диапазон отсутствует при <14 днях данных (не падает).
- **Cross-consumer consistency (добавить):** один факт (диагноз, диапазон ВСР) в
  `hai_core`-промпте, в `wellally` data package и в lifestyle-инжекте выводится из
  ОДНОГО значения БД — поменять `medical.diagnosis` в БД → измениться во всех трёх.
- **Placeholder-инвариант (добавить):** для каждого `lifestyle_*.md` после подстановки
  не остаётся `%%PATIENT_PROFILE%%`; при пустом профиле — нейтральный маркер, не литерал.

### Charter (человек)
1. Запустить реальный `/consult` (MDT) — прочитать вход всех 13 участников: профиль

   нет утечки порогов («HRV<15»)?
2. **Попытка сломать degraded:** временно «уронить» БД (переименовать health.db) →
   чат и MDT отдают нейтральный «профиль недоступен», не падают и НЕ показывают старый литерал.
3. **Попытка вернуть хардкод:** прописать в `specialists/lifestyle_sleep.md` строку
   «GENE AA (патогенный)» и закоммитить — guardrail обязан заблокировать.
4. Проверить, что `lifestyle_agents` (читает .md САМ, мимо wellally) тоже подставляет
   профиль — не показывает сырой `%%PATIENT_PROFILE%%`.
