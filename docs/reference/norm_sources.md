# Откуда брать норму: карта принятых источников

*Тип документа: справочник. Каталог внешних источников нормы по её ВИДУ (`docs/explanation/norm_kinds.md`), с оценкой надёжности, доступа и каденции пересмотра.*
*Собран 2026-09-02 по поиску и первичным документам; что не открывалось — помечено. Ни одно число отсюда в `absolute_thresholds` не перенесено: перенос — вердикт человека (§13).*

---

## 0. Главный вывод замера

Пороги, на которых стоит `safety_net` с апреля, — не «мусор случайный», а **полу-запомненный CTCAE**: HGB 12/10/8 — это грейды 1/2/3 анемии (`<LLN–10`, `<10–8`, `<8 g/dL`); PLT 100/50/20 — искажённые грейды (в CTCAE 75/50/25 ×10³); ALT «3x/7x ULN» — CTCAE даёт 3x/5x/20x. То есть модель пересказала шкалу токсичности онкотерапии, не назвав её и переврав цифры. Это одновременно плохая новость (числа неверны) и хорошая: **правильный документ для вида «порог решения» у пациента после онкологии — CTCAE, он открытый, версионируемый и имеет дату.**

Второе: CTCAE выражает грейды через **кратные ULN/LLN** — то есть требует на входе референс *той лаборатории, что сделала анализ*. Пороги решения не заменяют референс, а **композируются** с ним. Это прямо задаёт архитектуру: `reference_interval` берётся с бланка (уже лежит в `lab_results.ref_low/ref_high`), `decision_threshold` — из документа как множитель или абсолют, и одно без другого не работает.

Третье — и здесь я сам себя поправляю в тот же день. Первый замер по одному исследованию (Erden 2008, [DOI](https://doi.org/10.1080/00365510701601699), 49 здоровых, 4 точки) дал CV_I 27–31% и RCV 65–73% для CA 19-9/CEA, и я написал «наш trend-порог 50% ниже шума». **EFLM-база отдаёт JSON** (`GET https://biologicalvariation.eu/api/measurands`, 326 измерандов, без ключа) с мета-оценками BIVAC-совместимых исследований: CV_I для CEA — **медиана 6.8%** (ДИ 6.4–30.9, n=3), для CA 19-9 — **4.3%** (4.0–27.2, n=3), для ALT 12.6%, креатинина 4.4%, Hb 2.7%. Erden — верхняя граница интервала, выброс. С медианой и желательной аналитической точностью CV_A = 0.5·CV_I односторонний RCV для CEA ≈ 20%, CA 19-9 ≈ 13% — наш 50% **не ниже шума, а втрое выше**, то есть глухой. Урок тот же, что в §0 п.1: одно исследование — не источник; мета-оценка с рейтингом — источник, и она машиночитаема.

## 2. Вид 4 — личная норма и биологическая вариация

| Источник | Что даёт | Доступ | Надёжность | Каденция |
|---|---|---|---|---|
| **EFLM Biological Variation Database** (biologicalvariation.eu) | CV_I, CV_G по 132 измерандам (глобальные мета-оценки), >2400 датасетов из ~550 публикаций; калькулятор RCV с вашим CV_A; спецификации аналитического качества | **Бесплатно, без регистрации; JSON API `/api/measurands`** (медиана, ДИ, число исследований, матрица, `updated_at` — готовый датчик свежести) | Каждое исследование прогнано через BIVAC (оценка A–D), мета-анализ только BIVAC-совместимых; стандарт отчётности STARBIV (2024) | Живая, пополняется |
| Первичные BV-исследования по онкомаркерам | Erden 2008 (см. §0): CA19-9/CEA/AFP на Architect | PubMed | Одно исследование, 49 здоровых, 4 точки — низкий BIVAC-класс вероятен | — |

**Что применимо.** RCV = √2 · Z · √(CV_A² + CV_I²). CV_I — из EFLM, CV_A — спросить у лаборатории (внутрилабораторная воспроизводимость по аналиту; они обязаны её знать) либо взять из EFLM-спецификаций как верхнюю границу. Это единственный корректный способ ответить «сдвиг в ряду больше шума?» — и он бьёт наш `p10_personal` по 90 дням и `lab_trend_thresholds` 50%. Индекс индивидуальности CV_I/CV_G < 0.6 говорит, что для аналита популяционный интервал бесполезен и нужна личная база (креатинин, ТТГ, ферритин, онкомаркеры).

**Что применимо.** Для человека после онкологии вид 2 — это **CTCAE-грейды (композируемые с бланком) + кадансы наблюдения из ASCO/ESMO/NCCN по типу опухоли**. Какой гайдлайн применим — определяет диагноз, который называет врач. Если нужных фактов нет в `patient_profile`, система не должна выводить их из доступных анализов.

## 4. Вид 3 — стратифицированная цель

Здесь общедоступного «справочника» нет и быть не может: цель под анамнез назначает врач по гайдлайну (ESC-категории риска для LDL; NCCN-рискстратификация по стадии). Источники те же, что в §3, но применяются через факт профиля. Проект может хранить только **что врач сказал** и **из какого документа** — `stratum` + `source`.

## 6. Что из этого — в проект (предложение, не решение)

1. **Референс — с бланка**, и только с него; AACB/Mayo — второй свидетель на абсурд. Уже почти есть: `check_norm_vs_lab_reference`.
2. **Пороги решения по лабам — CTCAE v6 (2025-07-22)**, записанные как *множители ULN/LLN* или абсолюты с `source='CTCAE_6.0'`, `source_date='2025-07-22'`, `next_review` = выход v7 (проверять ежегодно). Все 64 «квитанционные» строки `safety_net` заменяются этим документом — не переписываются, а **выводятся**.
3. **Онкомаркеры — RCV из EFLM API + CV_A** (желательная APS 0.5·CV_I, пока лаборатория не дала свою), не 50% и не верх референса. Верх референса бланка для онкомаркера — это вид 1, для наблюдения после онкологии он вторичен по отношению к *динамике* (NACB 2008, ASCO 2013).
4. **Кадансы наблюдения (CEA/CA19-9 каждые 3–6 мес)** — это `lab_monitoring_schedule` с `source`, сейчас там `code_seed` у всех 19 строк.
5. `next_review` по видам: ADA — 1 год; CTCAE — проверка версии 1 год; ESMO/ESC — 2 года с проверкой eUpdate; бланк — на каждом новом документе автоматически.

## 7. Что не проверено / где я слаб

- Изменения **CTCAE v6 vs v5** не прочитаны; таблица в §3 — из v5.0 (кроме анемии, сверена с v6).
- **ESMO** полные тексты не открывались (403), кадансы по поджелудочной не извлечены.
- **GRID**: есть ли выгрузка/API — не установлено.
- Все «каденции» гайдлайнов — по факту дат прошлых версий, формальных обязательств пересмотра у большинства нет.
- Локальная лаборатория: её **CV_A** и документ о верификации референсов — не запрашивались. Это шаг владельца.
