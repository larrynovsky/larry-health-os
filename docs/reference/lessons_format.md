# Формат дома извлечённых уроков (`lessons.yaml`)

Один движок — `project_context/lessons.py` в health_scripts. У каждого проекта свой файл
`lessons.yaml` в корне: health_scripts и два соседних проекта. Ритуалы letitbe и the-end зовут
одну команду из корня любого из них.

## Команды

| Команда | Что делает |
|---|---|
| `python3 -m project_context lessons` | проверка формы; код 1 и список расхождений, 2 — дома нет |
| `… lessons --subject <ключ>` | что подать на старте работы по предмету (статусы из `deliver_statuses`) |
| `… lessons --subjects` | словарь ключей предмета проекта |
| `… lessons --modules a,b` | уроки по задетым модулям, любого статуса (так их печатает preflight) |
| `… lessons --groups` | сведение по (адрес, предмет); группа из 3 свидетельств созрела |
| `… lessons --selftest` | внесённые поломки обязаны покраснеть |

Движок живёт в health_scripts: из другого проекта — `PYTHONPATH=~/health_scripts`,
на MacBook интерпретатор `/opt/homebrew/bin/python3.11`. Корень — git-корень текущего
каталога либо `--root <путь>`.

## Шапка файла

| Ключ | Смысл |
|---|---|
| `address_kinds` | закрытый список видов адреса («что именно менять») |
| `subjects` | словарь ключей предмета; ключ — латиница в нижнем регистре; растёт только здесь |
| `homes` | необязательно: вид адреса → `{file, section}`; `ref` урока ищется КЛЮЧОМ в этом доме; `file` — плоское имя `*.yaml` в корне |
| `deliver_statuses` | необязательно: какие статусы подаёт `--subject`; по умолчанию `[adopted, failed]` |
| `adoption_dates` | необязательно: `required` — у каждого adopted обязана быть `adopted_on` |

## Запись урока

Обязательные поля: `id`, `date`, `thread`, `event` (что случилось), `cost` (во что обошлось),
`cause` (причина в устройстве, не в исполнителе), `address` (`{kind, ref}`), `subject`
(ключи из словаря), `outcome` (`{kind: rule|check|none, text}`), `status`, `evidence`, `owner`.

- `status`: observation · in_work · adopted · failed · confirmed. adopted/failed/confirmed
  требуют `change` — ссылку на сделанное изменение.
- `adopted_on`: дата внедрения `ГГГГ-ММ-ДД`. Урок той же группы (адрес + ключ предмета),
  записанный ПОЗЖЕ неё, красит стража: «правило не сработало» — поставь failed у
  внедрённых уроков группы. Тот же день повтором не считается.
- `evidence`: путь в репозитории либо `git:<sha>` — коммит, несущий след.
- `modules`: необязательно; список модулей, по которым урок печатает preflight.

Страж краснеет на пропущенном поле, адресе вне списка, ключе вне словаря, исходе вне трёх,
причине, сведённой к исполнителю, adopted без `change`, несуществующей улике, повторном id,
доме, который не читается, на принятой записи дома, не пересмотренной после урока,
на adopted без `adopted_on` (при `adoption_dates: required`) и на повторе после внедрения.
Честность причины он не проверяет — это суждение человека на выборке.
