# Движок гипотез: генерация, жизненный цикл, сходимость

> **Тип документа:** Explanation (Diataxis) — замысел, не рецепт.
> Управление: дашборд (карточки гипотез, кнопки `confirm`/`reject`/`eval`),
> Telegram (`/hypotheses`, `/confirm`, `/hreject`, `/hyp <id>`).
> Схема хранения (`memory` category=`hypothesis`, `hypotheses_cbcr`): [ARCH_SNAPSHOT.md](../../ARCH_SNAPSHOT.md).

**Идея.** Система формулирует гипотезы о здоровье пациента **из его данных** (метрики,
лабы, корреляции, дрейф) и доводит их до вывода через повторную оценку консилиумом.
Это заменило старый механизм «эксперименты» (см. надгробие внизу).

---

## Генерация

Гипотеза = `{observation, mechanism, prediction, test}` в `memory`
(`save_hypothesis`, `status="open"` по умолчанию). Источники (`trigger`):

- **`monthly_consilium`** (основной, 1-е число месяца) — панель из 11 агентов
  (9 врачей + 4 lifestyle) читает данные и выдаёт консенсус-гипотезы. Полный
  разбор — в `hypotheses_cbcr`.
- вторичные: `drift` (streak метрики ≥3), `correlation_drift`, `specialist_review`,
  `literature`, `survivorship`, ручной ввод.

Корреляции во входе консилиума — ТОЛЬКО из принятой веры (`belief_contract`, тем же
читателем `gp_context._build_longitudinal_correlations_block`, что у GP). До 2026-09-03 вход
печатал `hai_analysis.detect_correlation_drift` (Spearman 90/90 без перестановок и FDR,
включая производные пары): консилиум получил дрейф `r` для пары шаги↔активные ккал —
пары, которую гейт по `derived_filter` не пускает по построению, — и Movement Coach вывел
из неё связь с лабораторным показателем и геном. Это второй производитель `r` мимо гейта; UC-B-09 ловил ровно
этот случай. Суточный дрейф корреляций замысел уже назвал шумом (`drift_birth_defunct`).
Пустая вера подаётся явной строкой-запретом, не тишиной. Оракул —
`tests/unit/test_consilium_correlations_from_belief.py` (негативный контроль: детектор
дрейфа возвращает находку, во входе её нет).

**Дедуп — семантический** (`hypothesis_semantic_check`, Haiku): перед сохранением
кандидат сравнивается по СМЫСЛУ с открытыми/недавно-отвергнутыми. Дубль → пропуск
(аудит в `dedup_skipped`, `active=0`). Не даёт консилиуму плодить копии уже
отслеживаемой гипотезы.

## Жизненный цикл и ДВА смысла «подтверждено»

Ключевое: на дашборде есть **две разные** подтверждающие кнопки — не путать.

**1. `confirm` (быстрая пометка, `api_status_actions`).**
«Принимаю гипотезу к проверке» → `status="confirmed"`, `resolved_as`, `active=1`,
+ создаётся follow-up **задача** из поля `test` (сдать анализы / действие).
**Протокол НЕ рождается. Круг НЕ идёт.** Это личный триаж владельца.

**2. `eval` (консилиум → `resolve_hypothesis`).**
Запускает полный МДТ-консилиум (`evaluate_hypothesis_via_consilium`: 2 круга ×13
агентов + координатор + арбитр) против лабной истории → вердикт:
- **partial** → текущее в `history[]`, применяется `revised_hypothesis`, `version+1`,
  `status="open"` → гипотеза уходит **на следующий круг**;
- **confirmed** → протокол (`generate_protocol_from_hypothesis`), **но только
  если есть лаб, взятый после `created_date` гипотезы** (fresh-evidence guard,
  G3). Нет out-of-sample анализа → протокол отложен (`protocol_withheld`),
  гипотеза остаётся `open` и ждёт следующего круга; задача из `test` всё равно
  создаётся (она и подталкивает сдать нужный анализ);
- **rejected** → закрыта (+ иногда уточнённая наследница).

**Как результат `eval` доходит до человека (2026-08-29).** Консилиум идёт 2–3 минуты,
и хендлер дашборда его **не ждёт**: ставит замок в payload (`status="testing"`,
`eval_started_at`, TTL `dashboard_filters.EVAL_TTL_MIN`) и запускает **отдельный процесс**
`hypothesis_resolution.py --eval <id>` (`start_new_session`, лог `logs/consilium_eval.log`).
Не задачу в event loop — её убивал post-commit хук, перезапускающий дашборд на каждом коммите
(30.08: два консилиума погибли на Раунде B). Карточка возвращается сразу и опрашивает `GET /api/hypotheses/{id}/card`
каждые 5 с, пока замок жив; второй клик при живом замке консилиум не запускает.
Заключение при этом пишется в `hypothesis_outcomes` с `sent_at=NULL`, и в Telegram
его несёт outbox бота (`jobs.scheduled.deliver_unsent_outcomes`, на старте и каждые
5 мин) — не HTTP-ответ. Урок дня: девять консилиумов отработали в пустоту, потому
что оба канала (ответ на 170-секундный запрос и outbox только-на-старте-бота)
зависели от того, кто ещё жив в момент готовности результата. Понедельничный
`check_hypothesis_evaluations` подбирает `testing` без outcome **за текущий круг** (outcome
старше `eval_started_at` не считается) — решение владельца 30.08.

## Модель сходимости и fresh-evidence guard

Гипотеза **не регенерируется** каждый месяц — одна и та же строка `memory`
переживает круги, накапливая `version`/`history`. Сходимость эмерджентна:
несколько кругов `eval` (после каждого прихода анализов) отсекают альтернативы,
пока не останется одна. Поэтому молодая гипотеза в `partial`/`open` — норма, а не
застой; аномалия — «застряла в partial после ≥N кругов» (датчик такого класса —
открытая задача, заменяет снятый «гипотезы без экспериментов»).

**Что гейтит эскалацию — не счётчик кругов, а свежие данные (G3, 2026-07-13).**
Раньше `confirmed` за один `eval` сразу рождал протокол — даже если вердикт стоял
на уже существовавшей лабной истории (in-sample подгонка под данные, что были в
момент рождения гипотезы). Теперь `resolve_hypothesis` разрешает протокол только
при **out-of-sample** подтверждении: должен существовать лаб с датой позже
`created_date` (`_has_out_of_sample_lab`; читает ту же `get_lab_history`, что и
`eval`). Инвариант — блокируем только при доказанном отсутствии свежих данных;
любая неоднозначность (нет `created_date`, чтение лабов упало) трактуется в пользу
вердикта панели (fail-open). Guard **temporal-only**: проверяет, что лаб взят
позже, но не что он относится к предсказанию — релевантность оставлена консилиуму
(осознанно).

**Оператор в петле — сознательно.** `eval` запускает человек (кнопка), а не крон:
владелец следит за статусом каждой гипотезы, чтобы он не менялся сам.

**Известный разрыв (BL, шаг «врач»):** `_build_eval_data_package` кормит консилиум
только гипотезой + лабной историей (2 года). Мнение врача автоматически не
втекает — попадёт, только если вписать его в формулировку гипотезы вручную.

## Надгробие: «эксперименты» (ретайр 2026-07-10, BL-EXP-1)

Раньше существовал конвейер **N-of-1 экспериментов**: гипотеза → вмешательство →
baseline/target → check_days → attribution-отчёт → протокол. Владелец забраковал
его: эксперименты брались «из головы», а не из данных. Методика ушла к
data-born гипотезам консилиума, а сходимость — к версионированию самой гипотезы
(выше), не к экспериментам.

Ретайрено стадиями (снапшот `health.presnap_expretire_*`):
- приток остановлен (`hypothesis_lab_linker` → no-op; experiment-check снят из
  scheduled-джобы; интеграционный чек «гипотезы без экспериментов» снят);
- `resolve_hypothesis._close_experiment` → no-op (расцепка от `complete_experiment`);
- `experiments_db` — все функции no-op с прежними сигнатурами (health_db
  ре-экспорт + `check_contracts` целы; потребители сами отдают пусто);
- дашборд-эндпоинт `/experiments/{id}/{action}` снят;
- таблицы `experiments`/`experiment_log` **сняты** с канона (`db_regression` их
  исключает).

**Остаток (осознанно):** функции `experiments_db` и `gp_agent.run_experiment_checks`/
`generate_attribution_report` живут как документированные no-op стабы — полное
удаление трогает пиннед-контракт `check_contracts` + ~6 потребителей + их тесты
(высокий риск ради низкой ценности). Колонка `protocols.linked_experiment_id`
оставлена (nullable, сирота безопасна; протоколы НЕ ретайрятся — это валидный
выход confirmed-через-eval).
