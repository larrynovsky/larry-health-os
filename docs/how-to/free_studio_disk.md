# How-to: место на диске Studio кончается — куда смотреть

На одном диске Studio лежат канон, все его бэкапы и общий справочник шкал (BACKUP_POLICY §R2.5: оффсайта нет), поэтому кончившееся место бьёт по всему сразу. Документ написан по инциденту 02.11.2026 (72 ГБ свободного, из них ~33 ГБ съели снимки справочника за одно утро). Расширять по факту нового инцидента.

## Шаг 1 — сколько свободно и кто большой

```bash
ssh <studio_ssh> 'df -h /System/Volumes/Data | tail -1; du -sh ~/.health_reference ~/health*/backups ~/container_backups ~/.colima 2>/dev/null'
```

Ночной датчик «Место на диске под докачку справочника PGS» краснеет, когда следующей докачке не хватит места, и в тексте называет висящие снимки.

## Шаг 2 — снимки справочника

```bash
ssh <studio_ssh> 'ls -la ~/.health_reference/snapshots/ 2>/dev/null'
```

В покое папка пуста. Файл в ней — прогон, после которого справочник не прошёл проверку (в канал ошибок ушло `R2_ref_check`). **Руками не удалять**: следующий прогон сам проверит справочник и удалит снимок, если тот цел; если не цел — нужен откат из этого снимка.

## Шаг 3 — удалил, а место не вернулось

Удалённый файл держит место, пока его держит кто-то ещё. Два держателя, найденные 02.11:

```bash
ssh <studio_ssh> 'tmutil listlocalsnapshots / | grep -c TimeMachine
for p in $(pgrep -f com.apple.Virtualization.VirtualMachine); do
  lsof -a -p $p +L1 2>/dev/null | awk "NR>1 {s+=\$7} END {printf \"%d: %.1f ГБ\n\", $p, s/1e9}"; done'
```

- **Локальные снимки Time Machine** — почасовые, живут около суток. Отпустят сами; сразу — `tmutil thinlocalsnapshots / <байт> 4` (теряются почасовые точки отката, решение владельца).
- **Виртуальная машина контейнеров** (colima) держит удалённые файлы, которые контейнер когда-то открывал, до своего перезапуска: 02.11 — 16,6 ГБ. Освобождает `colima restart health` (службы Health стоят меньше минуты; профиль `default` с соседними проектами не трогать). Не в 03:00–08:00: ночные бэкапы и задачи.

## Шаг 4 — проверить

```bash
ssh <studio_ssh> 'df -h /System/Volumes/Data | tail -1'
```

После `colima restart health` — бот жив: `docker --context colima-health ps` (все службы `Up`) и свежие строки в `/app/logs/bot_err.log` внутри `health-bot-1`.
