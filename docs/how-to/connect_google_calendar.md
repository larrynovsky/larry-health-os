# Как подключить Google Calendar

> Тип документа: How-to (Diátaxis). Для человека, который поставил систему по
> [уроку первой установки](../tutorials/first_install.md). Установщик работает в терминале
> на компьютере с Docker; владелец календаря входит своим аккаунтом Google в браузере.
> Браузер может быть на другом компьютере: адрес после входа вставляется в ожидающий
> терминал на машине с системой. Это может делать один человек или владелец с помощником.

Календарь необязателен. Подключение разрешает **читать все доступные вам для чтения календари**,
а не только поездки: события от двух дней назад до 30 дней вперёд. Менять или удалять события
система не может. Названия, места и даты поездок могут попасть в утренний отчёт, Telegram
и текст для настроенного поставщика модели — это не обработка только внутри этой машины.
После подключения система сможет показывать карточку перед поездкой.
Боту ключи и адрес авторизации не отправляйте: они дают доступ к календарю.

## 1. Получите JSON клиента в Google Cloud Console

Владелец установки создаёт приложение; владелец календаря потом разрешает ему чтение.

**Граница проверки, 02.10.2026:** закрытая консоль и живой обмен с Google здесь не проверены.
Ниже — порядок настройки, а не протокол пройденной установки. Названия пунктов могут
отличаться: новый интерфейс использует Google Auth Platform, старый — APIs & Services.
[Документация Google](https://developers.google.com/calendar/api/quickstart/python) — ориентир.

1. Войдите в [Google Cloud Console](https://console.cloud.google.com/) своим Google-аккаунтом.
   В переключателе проектов сверху выберите **New project**, задайте имя, например
   `Health Calendar`, нажмите **Create** и выберите созданный проект.
2. Откройте **APIs & Services → Library**, найдите **Google Calendar API**, нажмите **Enable**.
3. Откройте **Google Auth Platform → Branding → Get started** (в старом интерфейсе:
   **APIs & Services → OAuth consent screen**). Заполните название приложения, email поддержки
   и контактный email. Для обычного личного аккаунта выберите аудиторию **External**.
4. В **Audience** оставьте статус **Testing**; не нажимайте **Publish app**.
   В **Test users → Add users** добавьте email аккаунта, чей календарь подключаете, и сохраните.
   Если вы ставите систему себе, добавьте себя. В **Data Access → Add or remove scopes** выберите
   `https://www.googleapis.com/auth/calendar.readonly` и сохраните. В старом интерфейсе эти
   пункты — шаги **Scopes** и **Test users** экрана согласия.
5. Откройте **Clients → Create client** (старый интерфейс:
   **APIs & Services → Credentials → Create Credentials → OAuth client ID**).
   **Application type: Desktop app**. Задайте имя и нажмите **Create**.
   Не выбирайте Web application; отдельный адрес возврата в консоли для Desktop app не вводите.
6. Скачайте JSON клиента (**Download JSON** или значок скачивания рядом с клиентом).
   На хосте переименуйте скачанный файл в `google_calendar_client.json` и оставьте в `Downloads`.
   Нужен JSON OAuth-клиента Desktop app, не ключ service account и не API key.
   Если браузер на другой машине, сначала перенесите JSON в Downloads компьютера
   с Docker; не отправляйте его боту.

Для приложения в Testing разрешение с Calendar scope обычно требует повторной авторизации
через 7 дней. Это правило Google здесь не проверено; сверяйтесь с
[описанием срока refresh token](https://developers.google.com/identity/protocols/oauth2#expiration).
Если данные перестали приходить, повторите шаг 3 ниже. Переход в Production и требования
Google к проверке приложения выходят за пределы этой инструкции.

## 2. Положите клиент в ключи на хосте

На компьютере с Docker файл `google_calendar_client.json` уже лежит в `Downloads` после шага 1.
Рядом сохраните файл **простого текста** `google_calendar_account`: только email аккаунта,
который выберете при входе в Google, без кавычек, форматирования и добавочного `.txt`.
Этот файл позволяет читателю отклонить чужой аккаунт; без него личность календаря не проверяется.

Скопируйте оба файла одной штатной командой `install`: права `600` выставляются сразу.

```bash
cd ~/health-docker && install -m 600 "$HOME/Downloads/google_calendar_client.json" "$HOME/Downloads/google_calendar_account" secrets/
```

**На Linux, если ваш UID не 1000** (`id -u`) и ключи отданы контейнеру в шаге 4 урока,
используйте вместо неё команду, которая также выставит владельца:

```bash
cd ~/health-docker && sudo install -o 1000 -g 1000 -m 600 "$HOME/Downloads/google_calendar_client.json" "$HOME/Downloads/google_calendar_account" secrets/
```

После успешного копирования удалите две временные копии из Downloads и очистите корзину.
В стандартной установке `secrets/` смонтирован только для чтения как
`/home/health/.health_secrets`; OAuth-токен позже будет записан в постоянный том данных.

## 3. Разрешите доступ в своём браузере

Установщик запускает интерактивную команду; не добавляйте `-T`:

```bash
cd ~/health-docker && docker compose exec cron python3 google_calendar_fetcher.py --setup --manual
```

1. Терминал покажет ссылку. Владелец календаря открывает её в своём браузере
   (на этой или другой машине),
   выбирает аккаунт из `google_calendar_account` и разрешает **чтение** календаря.
   Если Google показывает предупреждение о тестовом приложении, продолжайте только для
   своего приложения из шага 1. Отказ в доступе означает, что нужно проверить test users и scope.
2. Браузер перейдёт на адрес, начинающийся с `http://localhost:9877/?`.
   Страница может показать «не удалось подключиться»: сервер возврата не запускается,
   это ожидаемо. Скопируйте **полный адрес из адресной строки**, включая `state` и `code`.
3. Вставьте его в запрос **Paste the full redirect URL (hidden)** в том же терминале и нажмите
   Enter. Ввод скрыт. Адрес относится только к этой попытке; его нельзя брать из старой вкладки.
4. Дождитесь «Токен сохранён». Авторизация записана с правами `600` в
   `/home/health/health/data/google_calendar_token.json` — внутри постоянного тома `health-home`.
   Каталог ключей не изменяется. Перезапуск служб и проброс порта не нужны.

В контейнере `--setup` сам выбирает ручной режим; `--manual` делает выбор явным.

## 4. Проверьте подключение

Установщик запускает загрузку сразу:

```bash
cd ~/health-docker && docker compose exec -T cron python3 google_calendar_fetcher.py
```

Ожидайте `Calendar cache: N событий` без ошибок и предупреждений получения календарей.
Ноль событий допустим, если календарь пуст в загружаемом интервале. Само сообщение
«Токен сохранён» подтверждает только авторизацию; эта команда проверяет доступ к Calendar API.
Ошибки отдельных календарей дают предупреждения даже при созданном кэше — проверьте их.

Проверьте время загрузки и число событий, не выводя их содержание:

```bash
cd ~/health-docker && docker compose exec -T cron python3 -c 'import json; from google_calendar_fetcher import cache_path; c = json.loads(cache_path().read_text()); print("Fetched:", c["fetched_at"], "Events:", len(c["events"]))'
```

Откройте `http://127.0.0.1:8001/` на компьютере с Docker. На другом компьютере этот
адрес означает его самого: откройте страницу на машине с системой или используйте
уже настроенный частный доступ Tailscale. Обновите главную страницу: «Календарь поездок» должен показать «Подключено».
Дальше загрузка идёт по расписанию `cron` каждый час. Карточка подтверждает свежесть кэша,
а не правильность аккаунта или наличие поездки. При несовпадении аккаунта читатель
блокирует события и пишет `CAL_TENANT_MISMATCH` в журналы потребителя календаря.


Например, событие «Рейс в Париж» на завтра с местом «Париж» становится кандидатом на
карточку со смыслом «завтра: поездка — Париж». Код ищет слова вроде «рейс», «отель»,
«поездка» в названии и месте; любое заполненное место тоже считается признаком поездки,
так что обычная встреча с адресом может попасть в кандидаты. В утреннем отчёте выбирается
одно событие на сегодня, завтра или послезавтра, предпочтительно с местом. Это кандидат:
отбор и подавление повторов могут не пропустить его в сообщение; доставка отдельной
карточки сразу после подключения не обещана.

Если разрешение протухло, загрузчик пытается продлить его; при неудаче пишет
`Token refresh failed` и не обновляет кэш. Читатель предупреждает в журнале после 3 часов,
а кэш старше 25 часов перестаёт отдавать. Отдельное сообщение вам о протухшем разрешении
в этом пути не подтверждено. Если карточка сообщает, что загрузка задержалась,
повторите команду из шага 4, прочитайте ошибку и заново разрешите доступ шагом 3.

## Если что-то пошло не так

| Сообщение или симптом | Что сделать |
|---|---|
| `--manual` не распознан | Образ старее этой инструкции. Обновите установку по уроку и повторите шаг 3 |
| «Файл клиента не найден» | Проверьте имя файла и монтирование ключей; клиент нужен в каталоге владельца приложения |
| `Unreadable/invalid google_calendar_client.json` | Скачайте JSON клиента типа Desktop app; проверьте права чтения UID 1000 |
| `access_denied`, пользователь не допущен | Добавьте выбранный Google-аккаунт в Test users; проверьте, что Calendar API включён |
| `Wrong state` или `Wrong redirect URL` | Завершите попытку и снова выполните шаг 3; вставьте полный адрес из новой вкладки |
| `Google OAuth exchange failed` | Проверьте клиент, доступ контейнера к интернету и повторите шаг 3 с новым адресом |
| `Google did not return a refresh token` | Повторите шаг 3 и подтвердите доступ; без refresh token подключение не сохраняется |
| `token could not be saved; access stopped` | Проверьте свободное место и права записи UID 1000 в DATA. Старый файл не заменяется при ошибке записи/замены; не делайте ключи записываемыми |
| `Token refresh failed` / «Нет действующего … токена» | Повторите шаг 3: разрешение могло истечь в Testing или быть отозвано |
| `CAL_TENANT_UNVERIFIED` / `CAL_TENANT_MISMATCH` | Запишите верный email в `google_calendar_account`; при входе в чужой аккаунт повторите шаг 3 с нужным |
| Токен есть, но карточка ждёт загрузки | Выполните шаг 4; прочитайте ошибки загрузки |

## Какие данные читаются и где они остаются

Разрешение `calendar.readonly` позволяет читать календарь, но не создавать, менять или удалять
события. Загрузчик обходит доступные календари с правами owner/writer/reader; это шире календаря
поездок. Он запрашивает события от двух дней назад до 30 дней вперёд. Полные ответы Google
могут включать описания и участников; эти поля в кэш не сохраняются.

В DATA сохраняются список календарей и их идентификаторы/названия, email основного календаря,
а у событий — ID, название, начало/конец, признак целого дня, место, название календаря и тип
события. Поездки выделяет читатель; сведения о них могут попасть в утренний отчёт, Telegram
и текст для настроенного поставщика модели. Подключение не означает, что весь календарь
остаётся только между Google и этой машиной.

OAuth-токен также хранится в DATA: резервная копия тома содержит и его. JSON клиента,
токен и адрес возврата не публикуйте и не присылайте боту. Чтобы отозвать доступ, удалите
разрешение приложения в [подключениях Google-аккаунта](https://myaccount.google.com/connections).
Отзыв не удаляет уже сохранённый локальный кэш или отправленные отчёты.
