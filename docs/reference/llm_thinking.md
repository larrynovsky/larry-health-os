# Думание моделей: данные, по которым система решает

Модель может подумать перед ответом. Думание тратит тот же лимит длины, что и ответ, поэтому
система решает о нём сама, по трём записям в данных. Код вызова говорит только две вещи: какая
это задача (`task=`) и какой длины нужен ответ (`max_tokens`).

## Режим задачи — `methodology/llm_task_modes.json`

| Поле | Значение |
|---|---|
| ключ | имя задачи: `модуль.функция`, второй вызов в той же функции — с `.2` |
| `mode` | `think` — думать; `read` — не думать; `disputed` — как `read`, пока замер на эталонах не решит |
| `why` | причина одной строкой |

Правило выбора (решение владельца 04.10): думать, где между входом и ответом есть вывод; не думать,
где ответ получается внимательным чтением.

## Как модель включает и выключает думание — `methodology/llm_providers.json`, `anthropic.thinking.models`

| Поле | Значение |
|---|---|
| ключ | имя модели; датированный снимок (`claude-haiku-4-5-20251001`) находит запись по префиксу |
| `think` | параметр включения; `"{reserve}"` заменяется запасом |
| `no_think` | параметр выключения или `null`, если без параметра модель не думает |
| `measured` | дата и что показал замер |

Состояние на 04.10:

| Модель | Включение | Выключение | Без параметра |
|---|---|---|---|
| `claude-sonnet-4-6` | `adaptive` | — | не думает |
| `claude-opus-4-7` | `adaptive` | — | не думает |
| `claude-haiku-4-5` | `enabled` + бюджет | — | не думает |
| `claude-sonnet-5-5` | `adaptive` | `between_tools` | думает |
| `claude-opus-5` | `adaptive` | `disabled` | думает |

Модели без записи система думание не включает и не выключает. Допущенная модель без записи —
красный тест `test_admitted_model_that_thinks_by_default_must_say_how_to_stop`.

## Запас под думание — `methodology/llm_admission_table.json`, `reasoning_reserve_tokens`

Число токенов, которое обёртка прибавляет к лимиту ответа, когда задача думает. Его пишет замер
проверки моделей; рукой не ставится. Нет числа — задача не думает.

## Что делает обёртка (`llm_client`)

1. Вызывающий сам передал `thinking` — ничего не меняет.
2. Задача `think`, у модели есть `think`, запас замерен — думание включено, лимит = ответ + запас,
   `temperature` убирается (с думанием API её не принимает).
3. Иначе, если у модели есть `no_think`, — думание выключено.
4. Ответ остановлен по лимиту и в нём нет текста — один повтор с удвоенным запасом; второй такой
   ответ остаётся громким сбоем (`NoTextInAnswer`).
5. Думающий вызов идёт потоком (`stream`): с запасом лимит велик, и обычный вызов SDK отклоняет
   («Streaming is required…», замер 04.10). Сколько ушло на думание, пишется в журнал расходов
   `logs/agent_api_spend.log` (поля `think_tokens`, `answer_limit`, `attempts`) — по нему запас
   пересчитывается из рабочих вызовов.

Касается только поставщика Anthropic. У OpenAI, Gemini и DeepSeek думанием управляет их профиль
поставщика, как раньше.
