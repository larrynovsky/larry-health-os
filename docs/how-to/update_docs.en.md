# How to update documentation when the project changes

> **Document type:** How-to (Diataxis).
> Documentation map: CLAUDE.md (private part).
> Deployment commands: [docs/how-to/git_workflow.md](git_workflow.md).

---

## When adding a new module (.py file)

1. If the module introduces a new INTENT, add a record to `subsystem_intent.yaml` (intent · code_anchors · invariants).
   If the module only implements an existing intent, add to that intent's `code_anchors`.
   Lessons from unexpected behavior (“the world turned out to be different”) go in `lessons.yaml` (C-NN; format — `docs/reference/lessons_format.md`), not here:
   `preflight` prints them for whoever is working. The prose section in BLUEPRINT was removed on August 2, 2026.
2. Add it to `ARCH_SNAPSHOT.md` — to the module table and dependency graph
3. If the module imports an external API, add it to `ARCH_SNAPSHOT.md §ВНЕШНИЕ ИНТЕГРАЦИИ`
4. Run `gen_blueprint.py` to update the autogenerated sections:

```bash
ssh <studio_ssh> "cd ~/health_scripts && /opt/homebrew/bin/python3.11 gen_blueprint.py"
# The generator runs on Studio (CLAUDE.md (private part) §8: canonical-only generation),
# but the result is fetched with git, NOT rsync (scripts removed 2026-06-28):
git fetch studio && git reset --hard studio/main
```

## When changing the database schema (a new table or column)

```bash
# Apply the migration on Studio:
ssh <studio_ssh> "/opt/homebrew/bin/python3.11 ~/health_scripts/health_db.py migrate"
```

Update `ARCH_SNAPSHOT.md §DB SCHEMA` — add CREATE TABLE or ALTER TABLE.

---

## For any significant code change

`doc_agent.py` adds an entry to `CHANGELOG.md` automatically: for a thread, when it closes (`scripts/thread_finish.sh`, an entry from the thread's commit subjects with the `[нить <slug>]` tag); for a commit directly to main, through the post-commit hook.
You do not need to run it manually. Check that the hook ran:

```bash
tail -5 ~/health_scripts/CHANGELOG.md
```

## Deployment commands (cheat sheet)

```bash
# In your MacBook working copy — check syntax before committing:
/opt/homebrew/bin/python3.11 -m py_compile <file>.py && echo OK

# Commit the edits on MacBook:
git add <file>
git commit -m 'docs: ...' -- <file>
# A direct commit to main triggers post-commit itself: git push studio main + restart.
# For work longer than one commit — a tree via scripts/thread_start.sh <slug>;
# after the commits, close the thread FROM THE MAIN copy:
cd ~/health_scripts
scripts/thread_finish.sh <slug>

# Verify delivery before trusting integrity (§12):
git fetch studio
git log studio/main   # contains the commit under test?

# Run integrity_tests:
ssh <studio_ssh> "/opt/homebrew/bin/python3.11 ~/health_scripts/integrity_tests.py 2>&1 | tail -15"
```

## When fixing tech debt

Remove the line from `BACKLOG.md`. `doc_agent` creates the `CHANGELOG.md` entry when a thread closes or through post-commit for a commit to `main`; do not add it manually (CLAUDE.md (private part) § C “Environment”).
