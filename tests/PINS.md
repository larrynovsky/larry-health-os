# PINS.md — реестр характеризационных пинов и их вердиктов

**Проблема (обзор трёх линз, 2026-07-02).** 135 характеризационных тестов в 21
файле `tests/unit/*_characterization.py` фиксируют поведение health_db «как
есть». Все несут шапку «behavior-preserving пины: „как есть“ ≠ „как правильно“».
Это честно, но недостаточно: пин, замораживающий **баг**, при следующем
рефакторинге будет *сопротивляться исправлению* — тест краснеет, когда баг
чинят. Через год никто не отличит защиту инварианта от окаменевшей ошибки.

**Решение — не вердиктить 135 разом** (непропорционально и породит поверхностные
ярлыки), а: (1) завести конвенцию `PIN-VERDICT`; (2) реестром зафиксировать
уже известные пины-над-багами; (3) ратчетом обязать НОВЫЕ характеризационные
файлы декларировать вердикт. 21 существующий файл — baseline (grandfathered):
их пины по умолчанию `design` пока не пересмотрены поштучно.

## Конвенция PIN-VERDICT

В характеризационном тесте, фиксирующем НЕ-очевидное поведение, ставь строку:

```python
# PIN-VERDICT: design   — поведение верное, пин защищает инвариант
# PIN-VERDICT: bug       — пин замораживает баг; при фиксе тест ОБНОВИТЬ (ссылка на BACKLOG)
# PIN-VERDICT: unknown   — не разобрано; решить до опоры на это поведение
```

Ратчет `test_pins_registry.py::test_new_characterization_files_declare_verdict`
требует хотя бы одну строку `PIN-VERDICT` в файлах вне baseline-списка.

## Baseline (grandfathered 2026-07-02)

21 файл `tests/unit/*_characterization.py` (135 пинов) на момент установки
конвенции. Их пины считаются `design` по умолчанию; пересмотр — оппортунистически
при касании соответствующего домена, не кампанией. Новые характеризационные
файлы под ратчетом обязаны декларировать `PIN-VERDICT`.
