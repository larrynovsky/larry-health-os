# Как подключить кольцо Oura

Для установки в Docker по [уроку первой установки](../tutorials/first_install.md).
Нужен терминал на компьютере, где работает система; если ставил помощник, этот шаг выполняете
с ним. В Oura входите своим аккаунтом в браузере: браузер может быть на другом компьютере,
а адрес после входа нужно вставить в тот же ожидающий терминал. Нужны аккаунт Oura,
синхронизированное кольцо и, для Gen3 и новее, действующая подписка Oura Membership.
Подключение разрешает системе читать сон, восстановление, активность, тренировки, SpO₂, стресс и устойчивость к стрессу.

Новый пользователь подключается через OAuth2: один раз разрешает доступ в браузере,
после чего система пытается обновлять доступ сама, пока разрешение действительно. Если личный токен уже есть, перейдите к последнему разделу.

## 1. Зарегистрируйте приложение в Oura

1. Откройте [новый портал разработчиков](https://developer.ouraring.com/applications),
   войдите своим аккаунтом Oura и создайте приложение в **Applications**.
2. Заполните обязательные поля:
   - **Display Name** — `Larry Health OS` или своё понятное имя.
   - **Description** — например, `Personal sleep and activity tracking`.
   - **Contact Email** — свой адрес электронной почты.
   - **Website** — `https://github.com/larrynovsky/larry-health-os`.
   - **Privacy Policy** — `https://github.com/larrynovsky/larry-health-os`.
   - **Terms of Service** — `https://github.com/larrynovsky/larry-health-os/blob/main/LICENSE`.
   - **Redirect URIs** — ровно `http://localhost:9876/callback/`, с последним `/`.
     Не меняйте порт и не указывайте адрес контейнера. Если **+ Add URI** добавила
     лишнюю пустую строку, удалите её перед созданием.
3. В форме **Scopes** все разрешения уже отмечены по умолчанию. Команда ниже запросит
   только четыре нужных импортёру: **daily**, **workout**, **spo2**, **stress**.
   Не снимайте эти четыре в настройках приложения.
4. Отметьте **I agree to the Oura API Agreement** и создайте приложение.
5. Откроется окно с **Client ID** и **Client Secret**, у каждого — кнопка копирования.
   Оставьте его открытым для следующего шага. Секрет не отправляйте боту или в чат.

**Проверено владельцем 02.10.2026:** приложение создано в новом портале с указанными
Website, Privacy Policy и Terms of Service. Обычная cloud-команда ниже успешно
подключила это приложение; отдельного OAuth-маршрута для нового портала не требуется.

## 2. Сохраните Client ID и Client Secret

На компьютере, где работает Docker, сохраните в `Downloads` два файла простого текста:
`oura_client_id` — только Client ID, `oura_client_secret` — только Client Secret.
Без кавычек, форматирования и добавочного `.txt`; например, TextEdit нужно переключить
в простой текст. Секрет не вставляется в команду и не остаётся в истории терминала.

Скопируйте оба файла одной штатной командой `install`: она сразу выставляет права `600`.
Каталог `secrets` уже создан установкой.

```bash
cd ~/health-docker && install -m 600 "$HOME/Downloads/oura_client_id" "$HOME/Downloads/oura_client_secret" secrets/
```

**На Linux, если ваш UID не 1000** (`id -u`) и ключи отданы контейнеру в шаге 4 урока,
вместо команды выше используйте эту — владелец и права задаются при копировании, без ручного chown:

```bash
cd ~/health-docker && sudo install -o 1000 -g 1000 -m 600 "$HOME/Downloads/oura_client_id" "$HOME/Downloads/oura_client_secret" secrets/
```

После успешного копирования удалите две временные копии из Downloads и очистите корзину.

## 3. Разрешите доступ один раз

Для приложений из нового и старого портала используется одна команда:

```bash
cd ~/health-docker && docker compose exec cron python3 oura_oauth.py
```

**Если вы подключились до добавления `stress`:** снова выполните эту команду и дайте
новое согласие. Обновление программы или refresh старого токена само не добавит разрешение.
Старый вариант `--portal developer` больше не поддерживается: его обмен через `moi`
дал HTTP 400 при живой проверке 02.10.2026. Если сохранился токен этого варианта,
переподключитесь командой выше; автоматического повторного обмена на другом адресе нет.

1. Терминал напечатает ссылку. Откройте её в браузере, где можете войти в свой Oura.
   Это может быть другой компьютер: возврат принимается копированием адреса, не сервером.
2. Войдите в Oura и проверьте аккаунт. На экране согласия переключатели доступа
   **выключены по умолчанию**: нажмите сами переключатели и включите запрошенные
   **daily**, **workout**, **spo2**, **stress**, затем нажмите **Allow**.
   Allow с выключенными переключателями дал `access_denied` при проверке владельцем 02.10.2026.
3. Браузер перейдёт на `http://localhost:9876/callback/?...` и покажет ошибку соединения.
   **Это ожидаемо:** сервер на этом порту не запускается, порты Docker пробрасывать не нужно.
4. Скопируйте **полный адрес из адресной строки**, включая `code=...` и `state=...`.
   Вставьте его в ожидающий терминал и нажмите Enter. Вставляемый адрес скрыт — символы не появятся.
   Адрес содержит одноразовый код доступа: не отправляйте его в чат.
5. Дождитесь `Oura OAuth connected`. Разрешение сохранено в `data/oura_oauth.json` с правами 600.

В стандартной Docker-установке это `/home/health/health/data/oura_oauth.json` внутри контейнера,
в постоянном томе `health-home` (раскладка установщика проверена 02.10.2026). Это не файл
в `~/health-docker/secrets` на хосте. Каталог ключей внутри контейнера доступен только для чтения,
поэтому и первая авторизация, и обновления записываются в данные. Включайте том с этим файлом
в защищённые резервные копии; не кладите файл в git.
Не копируйте старый OAuth-файл поверх нового: refresh token одноразовый.

## 4. Проверьте импорт

После синхронизации кольца с приложением Oura:

```bash
cd ~/health-docker && docker compose exec -T cron python3 import_oura.py 3
```

`3` означает: начало запроса — текущая дата минус три дня, конец — текущая дата.
Это не число колец, файлов или попыток; без аргумента код берёт 30 дней.

В логе должен быть источник `Oura token source: OAuth2` и число сохранённых дней.
Ноль дней сам по себе не подтверждает подключение: проверьте синхронизацию кольца и ошибки API.
Откройте `http://127.0.0.1:8001/` в браузере **на компьютере, где работает Docker**.
На другом компьютере этот адрес означает его самого: используйте уже настроенный
частный доступ Tailscale или откройте страницу на машине с системой. При наличии данных
карточка «Сон и восстановление» покажет дату ночи; без данных ждёт поступления.
Первое подключение и импорт через cloud-маршрут владелец проверил 02.10.2026.
Доступ к `daily_resilience` требует `stress`: до добавления этого разрешения получен 401.
Проверка нового согласия со `stress` и последующего импорта ещё предстоит владельцу
после обновления программы; прежний успешный импорт её не заменяет.

Команда импорта сама не отправляет сообщение боту: данные могут войти в следующий
утренний отчёт. Дальше импорт выполняется по расписанию.

Если разрешение отозвано или обновление не удалось, OAuth не переключается на PAT.
Повторите команду импорта выше: она покажет ошибку; затем заново пройдите шаг 3.
Файл токена может остаться на месте — его наличие не доказывает действующий доступ.

## Если не получилось

- **Missing/unreadable / Empty oura_client…** — файл отсутствует, пуст или контейнер не может его
  прочитать. Проверьте имена файлов, каталог и владельца, затем повторите шаги 2–3.
- **Wrong state** — адрес из другого запуска или обрезан. Запустите шаг 3 заново и вставьте адрес
  именно из новой попытки. Обмен кода при этой ошибке не выполняется.
- **Wrong redirect / invalid_redirect_uri** — сравните URI в Oura с `http://localhost:9876/callback/`,
  включая порт и последний `/`. В терминал нужен адрес после одобрения, а не первоначальная ссылка.
- **authorization denied / access_denied** — включите сами переключатели запрошенного доступа, затем Allow; начните шаг 3 заново.
- **HTTP 400/401 при обмене** — возможны неверные client id/secret, устаревший код или
  израсходованный refresh token. Проверьте файлы клиента и используйте единственную команду шага 3 для нового кода.
  Тело ошибки не печатается, поэтому точную причину команда не устанавливает.
- **could not be saved in data** — каталог данных недоступен для записи или диск заполнен.
  Импорт остановлен: новый доступ не используется и перехода на PAT нет. Исправьте запись и повторите
  авторизацию: сервер мог уже заменить refresh token, старый файл не восстанавливает доступ.
- **network or invalid JSON** — связь оборвалась или ответ непригоден. После неясного результата
  обновления безопаснее пройти шаг 3 заново: неизвестно, успел ли сервер заменить refresh token.
- **401/403 при импорте** — доступ отозван, разрешения не выданы или подписка неактивна.
  Проверьте Membership и заново одобрите нужные разрешения. Работу с Oura проверяют импорт и данные,
  а наличие OAuth-файла на карточке означает только «подключение настроено».

## Если у вас уже есть личный токен (PAT)

OAuth не обязателен для работающего PAT. На 02.10.2026 публичные материалы помечают PAT устаревшими;
возможность выпустить новый и срок жизни старого здесь не проверены. Существующий токен положите
файлом `oura_token`, как раньше.

**Docker**:

```bash
printf '%s' 'TOKEN' > ~/health-docker/secrets/oura_token && chmod 600 ~/health-docker/secrets/oura_token
```

**Docker на Linux**:

```bash
printf '%s' 'TOKEN' | sudo tee ~/health-docker/secrets/oura_token >/dev/null
sudo chown 1000:1000 ~/health-docker/secrets/oura_token
sudo chmod 600 ~/health-docker/secrets/oura_token
```

Проверьте импорт командой из шага 4; источник будет `Oura token source: PAT`.
Если существует OAuth-разрешение в `data/oura_oauth.json` или в каталоге ключей, используется OAuth.
Ошибка OAuth не переключает систему на PAT. Чтобы сознательно вернуться к PAT, уберите оба OAuth-файла
из их рабочих каталогов, сохранив защищённую резервную копию. Отозванный PAT заменяется OAuth через шаги 1–3.
