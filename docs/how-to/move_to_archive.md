# How-to: убрать документ из LIVE в историю

Рецепт для случая «документ описывает завершённое, но удалять его жалко».

> Переписан 2026-08-04 после замера: прежняя редакция вела в `docs/archive/` —
> каталога с таким именем в репозитории нет и никогда не было. Заодно она
> ссылалась на несуществующий тест и на файлы-примеры, которых нет. Проверять
> рецепт исполнением, а не чтением, — дешевле, чем потом искать второй дом.

## Когда убирать

| Критерий | Пример |
|---|---|
| Описывает удалённую инфраструктуру | VPS-эра после миграции на Studio 2026-05-09 |
| Описывает завершённый разовый процесс | план работ с пометкой ЗАКРЫТО, отчёт об аудите |
| Содержит stop-words из `doc_inventory.yaml::stop_words_in_live` и переписать нельзя | старые сетевые адреса — если это исторический контекст |
| Устарело, но нужно для расследования | SECURITY-инциденты до текущей политики |

**НЕ убирать**, если документ можно обновить под текущее состояние. История —
это «зафиксировано на момент X», а не «лень переписать».

## Куда именно

Дом зависит от того, что за документ:

| Что | Дом | Почему |
|---|---|---|
| Разовый план, отчёт, аудит, решение владельца | `plans/` | `doc_inventory.yaml::archive` содержит `plans/*.md`; там 21 такой файл |
| Закрытый долг | `BACKLOG_ARCHIVE.md` | секцией внутри, не файлом |
| Снимок нити между сессиями | `docs/handoff/<нить>/` | пишет ритуал `the-end`, руками не создавать |
| Запись о поставке | `CHANGELOG.md` | пишет `doc_agent` при закрытии нити (`thread_finish`) |

**Каталога `docs/archive/` не существует — не создавай его.** До 2026-08-04 на
него смотрели два механизма вхолостую: append-only guard в
`scripts/git-hooks/pre_commit_check.py` и фильтр в
`tests/integration/test_doc_invariants.py:211`. Guard перенаправлен на `plans/`
(и несёт `_selftest_append_only`), мёртвый фильтр снят — в `plans/` GEN-блоков нет.

**Следствие для этого рецепта:** файл, уехавший в `plans/`, удалить обычным
коммитом уже нельзя — guard блокирует. Это по замыслу: он защищает от тихой
зачистки истории решений, на которую ссылается CLAUDE.md §15
(`plans/verify_*.py` как доказательства закрытых дыр). Удалять осознанно —
`git commit --no-verify`; содержимое в любом случае остаётся в истории git.

## Шаги

### 1. Перенести файл

Все правки и коммиты — на MacBook (§1, § Среда: Studio — deploy-only, коммит
там отклоняет pre-commit).

```bash
git mv docs/<раздел>/<FILE>.md plans/<ТИП>_<тема>_<YYYY-MM-DD>.md
```

Имя несёт дату — по ней документ читается как снимок момента. Конвенция
соседей: `PLAN_`, `AUDIT_`, `DECISIONS_`. Отдельная шапка «АРХИВ · заморожен»
**не нужна**: теста, который бы её требовал, в проекте нет, и ни один из 21
файла в `plans/` её не носит. Дата в имени и есть маркер.

### 2. Проверить классификацию

Отдельная запись в `doc_inventory.yaml` обычно не нужна: `plans/*.md` уже
покрыт glob'ом в `archive:`, а из `live:` файл выпадает вместе с
`docs/<раздел>/*.md`. Если переносишь в другой дом — сверь, что путь попадает
ровно в одну категорию (`test_no_file_in_both_categories`).

### 3. Снять страницу с учёта входов

Если файл числился в `doc_inventory.yaml::reader_path.frozen` — удалить строку
тем же коммитом и обновить `measured`. После переноса сторож
`test_doc_reader_path.py` эту страницу не видит (он смотрит `docs/**/*.md`), а
строка в `frozen` осталась бы указывать в пустоту.

### 4. Обновить входящие ссылки

```bash
grep -rn "<FILE>.md" --include="*.md" --include="*.py" .
```

Каждую ссылку — либо на актуальный LIVE-документ, либо явной пометкой
`[<название> (история)](../../plans/<новое-имя>.md)`.

### 5. Прогнать

```bash
HEALTH_DATA_DIR=~/health /opt/homebrew/bin/python3.11 -m pytest \
  tests/integration/test_doc_inventory.py \
  tests/integration/test_doc_invariants.py \
  tests/consistency/test_doc_reader_path.py -q
```

Что означают падения:

- `test_every_md_classified` — путь не попал ни в `live`, ни в `archive` → шаг 2.
- `test_no_file_in_both_categories` — попал в обе → шаг 2.
- `test_frozen_list_does_not_rot` — страница получила вход, но осталась в
  `frozen` → шаг 3.
- `INV-DOC-1` — в LIVE-файле остались stop-words → либо переписать упоминание,
  либо этот файл тоже уходит в историю.

### 6. Закоммитить

Незакоммиченное на canonical — латентная потеря (§1).

```bash
git add -A && git commit -m "docs: <FILE> в историю (<краткая причина>)"
```

## Чего не делать

- **Не удалять файл** вместо переноса, если на него ссылаются другие документы
  или аудит-логи. Удаление законно, когда ссылок нет и содержимое воспроизводимо
  из git.
- **Не оставлять в `live:` «временно»** — INV-DOC-1 будет красным каждую ночь и
  засорит утренний брифинг.
- **Не вычищать stop-words из исторического документа**, чтобы прошёл тест: это
  убивает его аудит-ценность.
- **Не создавать новый каталог под историю.** Дома перечислены выше; новый дом
  рядом с существующим разъезжается молча (§15, §18).
