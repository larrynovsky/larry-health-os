# How-to: коммит в main встал — разобрать ночные починки

Задача-рецепт для сессии агента. Ты получил при коммите или слиянии в `main` отказ
«⛔ commit в main заблокирован: ночной ремонт ждёт решения сессии» (код 15). Вот что делать.
Зачем замок устроен так — запись `night_decision_loop` в `subsystem_intent.yaml`.

Владелец в этой цепочке не участвует: починки читает и разбирает сессия. К нему идёт только
то, что может сделать или решить он один (действие на его телефоне, смена правила).

## Посмотреть, что лежит

```bash
python3.11 night_repair.py --gate; echo $?
python3.11 night_repair.py show <id>
```

`show` печатает карточку, диагноз ночного автора, ревью и патч. Слова автора и ревьюера —
гипотезы: проверь замером то, на чём стоит решение. Улики читай в живой базе владельца
(контейнер), а не в замороженной копии на хосте.

## Починка вида «код»

```bash
python3.11 night_repair.py land <id>
git commit
python3.11 night_repair.py close <id>
```

`land` сам гоняет тесты патча на стенде дважды — без правки (обязаны быть красными) и с ней
(обязаны быть зелёными) — и кладёт правку в индекс главной копии. `close` — после того, как
коммит доехал до Studio.

Ревью «доработать» или квитанция негативного контроля получена не тем прогоном, что в ней
назван, — не сливай как есть:

```bash
python3.11 night_repair.py reject <id> "почему; доделывается в нити <имя>"
scripts/thread_start.sh <имя>
```

Патч остаётся на Studio в `~/health/night_repair/rejected/<id>/fix.patch` — возьми его основой.
Карточку закрывает правка нити, а не отклонение.

## Починка вида «среда»

Правки нет: в `NIGHT_FIX.md` шаги. Сделай их, затем закрой словами — что измерено и что сделано:

```bash
python3.11 night_repair.py close <id> "что измерено и что сделано"
```

Шаг может сделать только владелец — передай ему одно действие простыми словами, сразу; в словах
закрытия назови, что осталось за ним.

## Проверить, что замок открыт

```bash
python3.11 night_repair.py --gate; echo $?
```

Ноль и пустой вывод — `main` снова принимает коммиты всех сессий.

## Чего не делать

- Не обходи замок `--no-verify`: он стоит решением владельца 30.09.
- Не закрывай починку словами автора — только своим замером.
- Перед `close` и `reject` перечитай список: метки «починку взяла сессия» нет, и соседняя
  сессия могла разобрать тот же id.
