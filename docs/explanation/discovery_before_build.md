# Discovery-до-постройки: почему карта-оракул выкинута, а дубль ловится по данным

> ADR · 2026-07-23 · статус: принято (владелец) · нить project-context
> Прочти это ПРЕЖДЕ, чем «улучшать» project_context новой картой/дайджестом,
> который агент должен читать, — этот путь пройден и закрыт экспериментом.

## Болезнь

Агент в накопленном контексте плодит дубли и не видит соседний код: пишет вторую
функцию тем же именем, не грепнув def (F-106: `get_active_protocols` ×2 —
protocols_db.py + hai_hypotheses.py; корпус C-07), или переделывает существующее
под другим именем. Ключевое свойство: дубль под ДРУГИМ именем невидим
греп-по-имени, но виден через ДАННЫЕ (таблицу/ключи), которые он трогает.
Способности заякорены на данные, не на имена.

## Эксперимент, закрывший карту-оракул (10/0, 2026-07-23)

Гипотеза была: preflight-дайджест (структурная карта подсистемы), который агент
ЧИТАЕТ перед задачей, предотвращает ложные пути. Проверка: 10 субагентов
(7 свежих + 3 с реально накопленным контекстом) на ловушках (дубль / смена
контракта / чтение) — НОЛЬ ложных путей и БЕЗ карты. Болезнь не воспроизвелась
даже под нагрузкой; накопленный контекст ПОМОГАЛ, не мешал. Пред-регистрированный
вывод: карта-как-чтение не оправдана предотвращением. Отдельно доказано: блайнд-eval
эту пользу в принципе не мерит (construct validity: бутафорская «нагрузка»
болезнь не воспроизводит; себя-вслепую нельзя — demand characteristics).

Что при этом СРАБОТАЛО вживую (T2): L2-гейт квитанций остановил коммит
нагруженного агента; тот не ушёл в `--no-verify`, прогнал preflight; корпусная
строка C-22 породила реальную проверку 586 callers. Формула: **принуждение
(гейт) + корпус ложных путей работают; структурная карта-как-чтение — нет.**

## Решение: три слоя вместо карты

1. **Global-правило** (Cowork Global Instructions, кросс-проект, ставит владелец):
   прежде чем писать новую функцию/модуль — найди существующее ПО ДАННЫМ
   (таблица/ключ), не только по имени. Условная часть («есть инструмент — зови»)
   сама гаснет в проектах без движка (RN-D).
2. **Discovery-инструмент**: `capabilities <имя|таблица>` — by_name + by_data
   (W/R-карты движка). Доставка — MCP-сервер `project_context/mcp_server.py`
   (решение владельца 2026-07-23; CLI-first отвергнут: shell-команду из памяти агент
   не зовёт, тул в списке инструментов — видит; это морковь против RN-F).
3. **Дубль-гейт на pre-commit** (`dupgate`): BLOCK на точный кросс-файл дубль
   имени, ВВЕДЁННЫЙ staged-диффом; WARN на «новая функция трогает чужую таблицу»
   (кандидат дубля по данным). Только новые имена — легаси не красится (RN-E).
   Включён после зелёных позит+негат контролей (tests/unit/test_dupgate.py, RN-B).

L2-квитанционный гейт ОСТАЁТСЯ (решение владельца: «l2 оставим»): он ловит класс
«не прогнал ритуал», дубль-гейт ловит результат. Это разные страховки.

## Отвергнуто (не пересобирать)

- **Карта-оракул / preflight-дайджест как чтение** — 10/0. Код `preflight` жив,
  но как генератор квитанций для L2-гейта, НЕ как контракт «прочитал → защищён».
- **Блайнд-eval как мера пользы** — не мерит (см. выше).
- **CLI-first для discovery** — перебит решением владельца в пользу MCP.
- **L0a-обогащение алертов (`enrich.py`)** — dormant: вшит в test_failure_handler,
  не развивается. Решение «оставить dormant» 2026-07-23.
- **Универсализация вперёд доказательства** — health первый, кросс-проект потом.

## Мера пользы: catch-log и его честные пределы

Единственная оставшаяся мера — обсервационная: `docs/reference/duplicate_catch_log.md`,
журнал реальных случаев (рано=discovery / поздно=гейт / проспан=нашёлся руками /
ложняк=WARN не подтвердился). Решение владельца 2026-07-23: журнал — рабочая ПАМЯТЬ
АГЕНТА (провенанс dup_allowlist, кандидаты в корпус), человек его не ревьюит.
Названное вслух следствие: человеческой меры пользы у системы нет; «проспан» —
цензурированная категория (видны только случайно найденные пропуски), журнал
даёт нижнюю границу пропусков, не полноту.

## Пределы

- Discovery видит только data/def-способности; чистая логика без БД невидима
  (RN-A). Вывод `capabilities` несёт scope-пометку; пустой результат ≠ «дублей нет».
- Шаг «позвать discovery» нефорсируем (нет пре-тул хука в среде; RN-F) —
  форсируется только РЕЗУЛЬТАТ (dupgate на коммите); трату работы на дубль,
  пойманный поздно, полностью не убрать.
- by_name — двусторонний substring, шумит (`protocols` → `cmd_protocols`);
  поэтому в гейте только ТОЧНОЕ совпадение имени, и только модульные функции
  (методы классов — интерфейс, не судим).
- by_data-эвристика гейта видит только SQL-литералы в теле новой функции;
  ORM/косвенные обращения не видит.
- При осознанном рефакторинге-копии (split файла) гейт зажжётся на честной
  копии — это фича (дублирование кода), выход: dup_allowlist или `--no-verify`.

## Onboarding-слой (дополнение 2026-07-23, вечер)

Тот же принцип, распространённый со способностей на знание: новый агент получает
существующее знание системы PULL'ом, не push-картой. Тул `project_intent` (тот же
MCP-сервер): каталог реестра замысла (id, title, статусы инвариантов — не-holds
видимы: «чему верить нельзя» важнее «что есть») → тёплая страница по id (байт-в-байт
с диска, без пересказов; единственный источник — git-дерево, чтение на каждый вызов) →
мост module→подсистема (цепочка данные→код→замысел замыкается с project_capabilities).
Страницы вне реестра отдаются с пометкой «свежесть не сторожится» + mtime; id — имя,
не путь (traversal отвергается контрактом). Указатель на замысел добавлен в
preflight-вывод — реюз единственного доказанного форс-момента (T2). НЕ строить поверх
этого: генерируемые сводки/обзоры (карта-оракул v2) и push-чтение «прочитал — защищён»
закрыты тем же экспериментом 10/0.
