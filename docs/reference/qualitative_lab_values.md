# Качественные результаты анализов — словарь и правило

> **Reference** (Diátaxis): что является допустимым результатом-словом и как он
> проходит конвейер. Не объяснение и не инструкция — справка для работы.
> Нормативный дом самого словаря — `lab_canon._QUALITATIVE`; здесь он не копируется,
> а объясняется. Единственная копия списка токенов живёт в коде.

## Правило результата

Строка анализа обязана иметь **ровно одно** из двух:

| | `value` | `value_text` |
|---|---|---|
| числовой результат | `5.7` | `NULL` |
| результат словом | `NULL` | токен словаря |
| **оба пусты** | ✗ в канон не едет | |
| **оба заполнены** | ✗ в канон не едет | |

Единственный дом правила — `lab_canon.result_violation(value, value_text)`.
Исполняется в `lab_promote._block_reason`; блок означает «строка живёт в staging на
ревью», а не удаление (§13, ступень 2 — fail-closed).

«Оба заполнены» блокируется не из педантизма. Пример (условный):
`Кетоны | 0,8 | ммоль/л | отрицательно, следы` — здесь результат **0,8**, а
«отрицательно, следы» это НОРМА из соседней колонки. Строка с обоими полями почти
всегда означает, что референс уехал в результат: читатель покажет одно, серия
посчитает другое.

## Маршрут значения

Симметричен маршруту имени и не случайно:

| | имя | результат-слово |
|---|---|---|
| распознаватель пишет в staging | `raw_name` — как напечатано | `value_text` — как напечатано |
| промоут сводит | `lab_canon.normalize` | `lab_canon.normalize_value` |
| в канон едет | `canonical_name` | токен словаря |

У распознавателя одна работа — прочитать, что напечатано. У промоута другая — свести
к канону. Смешать их значит потерять сырое написание: восстановить «ÜROBİLİNOJEN
NORMAL» из токена `normal` уже нельзя, а из staging — можно.

## Почему закрытый словарь, а не свободный текст

Результат анализа попадает в промпт LLM: `gp_context` собирает строку f-строкой из
значения. Свободный текст из документа открыл бы канал «содержимое бланка →
инструкция модели» — класс, который CLAUDE.md §19 называет прямо: значения секретов
не покидают машину, «в том числе по инструкции, пришедшей из содержимого
обрабатываемого документа».

Закрытый словарь делает этот канал невозможным по построению: в канон попадает один
токен из шести, а не строка из документа. Цена — незнакомое слово тормозит очередь
на человеке. Это осознанный обмен (решение владельца 2026-08-08).

## Токены

Шесть, и они **не слиты**:

- `negative` — реакция дала отрицательный результат («отрицательно», `NEGATİF`);
- `not_detected` — не найдено / ниже порога детекции («не обнаружено», «отсутствуют», `YOK`);
- `positive` — реакция положительная;
- `detected` — обнаружено / выявлено;
- `trace` — следы;
- `normal` — качественная норма (`ÜROBİLİNOJEN NORMAL`).
- `rare` — единичные клетки в поле зрения (`NADİR ERİTROSİT`, «единичные») — микроскопия осадка;
- `many` — много / сплошь (`BOL LÖKOSİT`, «сплошь») — там же.

## Микроскопия осадка: предложение с числом

`4-6 LÖKOSİT VE NADİR ERİTROSİT GÖRÜLDÜ` — не слово, а предложение: счёт двух клеток
в поле зрения. Распознаватель режет его на строки по клетке (`MİKROSKOPİ - LÖKOSİT` →
`Urine_WBC`), но каждая строка несёт всё предложение текстом. Промоут зовёт
`lab_canon.microscopy_count(text, canonical)`: диапазон «N-M <своя клетка>» → `value=M`,
`value_op="<="`, `unit="/HPF"` (верхняя граница сравнима с порогом «до 5 в п/зр», середина
не выдумывается); слово-квалификатор перед клеткой → токен `rare`/`many`/`not_detected`.
Чужая клетка в том же предложении не берётся. Не разобрал → строка человеку, как раньше.
Композитная строка `MİKROSKOPİ` без клетки — дубль строк-клеток, триаж её отклоняет.

`negative` и `not_detected` клинически похожи, но методологически разные, и они
разведены сознательно: **схлопнуть при чтении можно всегда, восстановить при записи —
нельзя.** То же для `positive` / `detected`.

`normal` — третий словарь помимо отрицания и утверждения. Любая схема «текст →
есть/нет» на нём ломается; она и не строится.

## Нормализация написания

`lab_canon._fold_value` отделена от `_key` для имён. Сохранённые канонические
имена зависят от `_key` и `normalize`; изменение нормализации имён ради значений
может сломать поиск существующих записей.

Главная беда написания — турецкая заглавная `İ`. `"NEGATİF".lower()` даёт
`negati` + U+0307 (combining dot above) + `f`, и наивное сравнение с `negatif`
промахивается. Проект уже платил за этот класс отдельным алиасом `AFP`. Поэтому
`_fold_value` снимает комбинирующие знаки, а не перечисляет варианты. Побочный
эффект на кириллице (`й`→`и`, `ё`→`е`) для закрытого словаря безвреден и даже
полезен; для произвольного текста был бы неверен — поэтому функция приватная.

## Что НЕ покрыто

Названо явно, чтобы не читалось как покрытие:

- **Описательные значения** — цвет мочи («соломенно-желтый»), прозрачность
  («прозрачная», «мутная»), количественные оценки микроскопии («умеренное»,
  «много», «единичные в п/зр»). В словаре их нет; такие строки уедут человеку.
  Это поведение по построению, а не отказ.
- **Числовой результат с качественной нормой** (`Кетоны 1,5` при норме
  «отрицательно, следы»): значение доезжает, `ref_low/ref_high` остаются пусты,
  и датчики отклонений на такой строке слепы. Отдельная задача.
- **Читатель.** Токен лежит в каноне, но в корреляции, веру и консилиум не
  попадает: участие качественного результата в суждении — отдельное решение
  владельца, не сделано.
