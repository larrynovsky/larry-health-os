# How-to: найти существующее ДО постройки (discovery + дубль-гейт)

## Перед новой функцией/модулем

1. Сформулируй задачу через данные: какая таблица/ключ её обслуживает?
2. Позови discovery: MCP-тул `project_capabilities` (если сервер зарегистрирован)
   или `/opt/homebrew/bin/python3.11 -m project_context capabilities <таблица|имя>`.
3. Главный вывод — `by_data`: кто уже трогает эти данные. Нашёл похожее →
   открой источник и переиспользуй/расширь, не строй параллель.
4. Пустой результат ≠ «дублей нет»: не-data способности инструменту не видны
   (scope-пометка в выводе, RN-A).

## Гейт заблокировал коммит (точный дубль имени)

- Правильный путь: переиспользуй существующую функцию (файл:строка в сообщении).
- Осознанный дубль (интерфейс/переходный период): имя в `dup_allowlist`
  в `project_context.json` + строка в `docs/reference/duplicate_catch_log.md`.
- Крайний случай: `git commit --no-verify` (пропускает ВСЕ хуки, след в логе).

## WARN «трогает таблицу, которую уже обслуживают»

Кандидат, не приговор: прогони `capabilities <таблица>`, сверь кандидатов.
Реальный дубль → переиспользуй. Ложняк → коммить можно (WARN не блокирует),
запиши исход в catch-log (ложняки — сырьё для тюнинга эвристики, RN-B).

## Регистрация MCP-сервера (шаг владельца, один раз)

В конфиг MCP-серверов Claude Desktop (рядом с Desktop Commander):

```json
"project-context": {
  "command": "/opt/homebrew/bin/python3.11",
  "args": ["-m", "project_context.mcp_server"],
  "env": {
    "PYTHONPATH": "~/health_scripts",
    "PROJECT_CONTEXT_ROOT": "~/health_scripts"
  }
}
```

Проверка: в новой сессии появляется тул `project_capabilities`; вызов с
`query="protocols"` возвращает `get_active_protocols` в `by_data`.

## Новый проект (кросс-проект)

Движок домен-агностичен. На той же машине пакет НЕ копируй — переиспользуй
через `PYTHONPATH=~/health_scripts` (одна копия движка; анти-дубль
не начинает жизнь с дубля самого себя): так в pre-commit, так и в discovery
(у MCP-тула есть параметр `root` — один сервер обслуживает все репо).
В корне проекта заведи `project_context.json` (можно `{}`), поставь
dupgate-секцию в pre-commit (fail-open: движка нет → пропуск). Отдельная
машина без health_scripts — тогда копия пакета. Нет манифеста → нейтраль;
discovery и гейт работают всё равно. Референс развёртки: соседний проект
(`scripts/hooks/macbook-pre-commit.sh`, 2026-07-23).

## Онбординг в существующее (project_intent)

Новая сессия, незнакомый проект: `project_intent` без аргументов → каталог подсистем
(это меню, не знание) → `project_intent id=<подсистема>` → замысел + инварианты со
статусами (не-holds = утверждению не верь) + тёплая страница → дальше в code_anchors.
Пришёл от файла, а не от вопроса — `project_intent module=<имя.py>` скажет, чья это
подсистема. Страницы «вне реестра» — без сторожа свежести: сверяй с кодом, смотри mtime.

Почему так устроено: `docs/explanation/discovery_before_build.md` (ADR).

## Если тул отвечает «корень проекта не существует»

Это отказ, а не ответ: сервер смотрит в каталог, которого нет. Оба тула
(`project_capabilities` и `project_intent` во всех формах) на мёртвом корне
отказывают, а не отвечают пустотой — пустота читалась как знание: «дублей нет»,
«реестр замысла не заведён». 22.09.2026 `project-context-mm` смотрел в удалённый
iCloud-путь соседнего проекта и на вопрос о замысле отвечал «реестра нет» при живом реестре.

Что делать: поправить `PROJECT_CONTEXT_ROOT` сервера в
`~/Library/Application Support/Claude/claude_desktop_config.json` и сразу
перезапустить Claude Desktop, либо передать `root=<путь>` аргументом вызова.
Правка, сделанная при запущенном приложении и не подхваченная перезапуском, может
быть затёрта: 22.09 секция `mcpServers` вернулась байт-в-байт к копии до правки
14.09 (причина — гипотеза, не доказана).

Сторож: `python3 -m project_context roots-check [<путь к конфигу>]` — exit 1 и имя
сервера, если чей-то корень мёртв. Зовётся из post-commit MacBook на каждом коммите.

Чего отказ НЕ означает: живой корень без `subsystem_intent.yaml` — законный случай,
он по-прежнему отвечает «реестр замысла не заведён», и это правда.
