# Первая установка Larry Health OS

Этот урок поднимает систему с нуля. К концу у вас будут работающие службы, свой Telegram-бот
и знакомство с ним. Медицинские данные для установки не нужны: в конце бот попросит
документы, и прислать их можно сразу или позже, когда захотите.

Система живёт в Докере — в «контейнерах». Контейнер — это закрытая коробка, внутри которой
уже лежат нужный Python, библиотеки и распознавание текста. Коробка собрана заранее и
одинакова на любой машине: вы ставите только сам Докер и скачиваете два файла настроек.
Ни клонировать репозиторий, ни собирать что-то самим не нужно.

Бот сначала предлагает выбрать русский или английский, после чего использует этот язык для
собственных текстов интерфейса. Тексты модели пока остаются русскими.

Что понадобится:

- Mac (Apple Silicon или Intel, macOS 13+) с [Homebrew](https://brew.sh), или Linux-машина
  с Docker Engine, или Windows 11 через WSL2 — этот путь пока не проверен, см.
  раздел «Windows через WSL2» ниже;
- около 4 ГБ свободной оперативной памяти и 20 ГБ на диске;
- аккаунт Telegram и ключ Anthropic API (около 5–15 € в месяц на человека);
- около 20 минут, из них несколько — первое скачивание образа.

Машина должна работать постоянно: утренний отчёт, напоминания и ночные проверки система
делает сама, по расписанию. Уснувший или выключенный компьютер ничего не пришлёт. На Маке
отключите сон (экран гаснуть может, машина — нет):

```bash
sudo pmset -a sleep 0
```

У ноутбука, кроме того, крышка должна оставаться открытой.

## 1. Поставьте Докер

На Маке Докер работает внутри маленькой виртуальной машины Colima. Если у вас стоит Docker
Desktop, закройте его: команда `docker` из Homebrew и из Docker Desktop мешают друг другу.
Поставьте Colima и сам Докер:

```bash
brew install colima docker docker-compose
colima start --profile health --cpu 2 --memory 4 --disk 20
```

Докеру нужно показать, где Homebrew положил его дополнение `compose`:

```bash
mkdir -p ~/.docker/cli-plugins
ln -sfn "$(brew --prefix)/opt/docker-compose/bin/docker-compose" ~/.docker/cli-plugins/docker-compose
```

Первый старт Colima занимает минуту-две. Colima запоминает эти размеры; `--profile health` даёт
виртуальной машине своё имя, чтобы она не смешалась с другими, если Докер у вас уже есть.
Проверьте, что Докер отвечает:

```bash
docker info --format '{{.ServerVersion}}'
```

В ответ — номер версии, например `27.4.1`. И дополнение на месте: `docker compose version`
печатает свою версию, а не `unknown command`. Команда `docker context ls` показывает звёздочку
у `colima-health` — значит, команды идут в эту виртуальную машину. Ошибка `Cannot connect to
the Docker daemon` значит, что Colima не запустилась: повторите `colima start --profile health`.

На Linux поставьте Docker Engine с дополнением `compose` по
[инструкции Докера](https://docs.docker.com/engine/install/), Colima там не нужна.

## 2. Скачайте файлы запуска

Заведите каталог, откуда система будет запускаться, и скачайте в него два файла последней
версии: `compose.yaml` (какие контейнеры запускать и из какого образа) и `.env` (их настройки).

<!-- tutorial:run -->
```bash
mkdir -p ~/health-docker && cd ~/health-docker
curl -fsSL -o compose.yaml https://github.com/larrynovsky/larry-health-os/releases/latest/download/compose.yaml
curl -fsSL -o .env https://github.com/larrynovsky/larry-health-os/releases/latest/download/health.env
grep 'image:' compose.yaml | sort -u
```

Последняя строка покажет имя образа с номером версии, например
`image: ghcr.io/larrynovsky/larry-health-os:v0.1.0`. **Все дальнейшие команды — из
`~/health-docker`.** Файлы руками не правьте, кроме часового пояса в следующем шаге.

## 3. Укажите часовой пояс

Система — это три постоянные службы (бот, дашборд и разборщик присланных файлов) и
планировщик, который исполняет около двадцати пяти задач по расписанию: утренний отчёт, импорт
данных, ночные проверки. Время задач — местное, поэтому системе нужен ваш пояс.

Узнайте его: на Маке `readlink /etc/localtime | sed 's#.*/zoneinfo/##'`, на Linux
`timedatectl show -p Timezone --value`. Ответ вида `Europe/Berlin` подставьте в первую строку
и выполните все четыре:

<!-- tutorial:run -->
```bash
cd ~/health-docker
MY_TZ=Europe/Berlin
sed -i.bak -e "s#^TZ=.*#TZ=$MY_TZ#" -e "s#^HEALTH_TZ=.*#HEALTH_TZ=$MY_TZ#" .env
grep 'TZ=' .env
```

`grep` должен показать две строки, `HEALTH_TZ=` и `TZ=`, обе с вашим поясом.

## 4. Заведите своего Telegram-бота и ключи

Бот — ваш единственный интерфейс к системе. Без `telegram_token` и `telegram_chat_id` он не
запустится, без `anthropic_key` не будут писаться отчёты.

1. В Telegram откройте `@BotFather`, отправьте `/newbot`. Он спросит имя (любое) и адрес,
   который обязан кончаться на `bot` (например `my_health_bot`). В ответ придут ссылка
   `t.me/<адрес>` — по ней вы потом найдёте своего бота — и токен вида `123456:ABC…`.
2. Узнайте свой числовой id: напишите `@userinfobot`, он ответит строкой `Id: 12345678`.
3. Ключ Anthropic API возьмите на console.anthropic.com: пополните баланс (раздел Billing) —
   без денег на счёте ключ выдаётся, но отчёты не пишутся, — затем создайте ключ (API Keys) и
   сразу скопируйте его: второй раз его не покажут.

Положите ключи в подкаталог `secrets` каталога запуска:

<!-- tutorial:run -->
```bash
mkdir -p ~/health-docker/secrets && chmod 700 ~/health-docker/secrets
cd ~/health-docker/secrets
printf '%s' 'ТОКЕН_ОТ_BOTFATHER' > telegram_token
printf '%s' 'ВАШ_ID' > telegram_chat_id
printf '%s' 'КЛЮЧ_ANTHROPIC' > anthropic_key
chmod 600 telegram_token telegram_chat_id anthropic_key
```

Заменяйте только текст внутри кавычек, сами кавычки оставьте. Для id — только цифры, например
`printf '%s' '12345678' > telegram_chat_id`. Контейнеры видят этот каталог только для чтения.
Бот отвечает только на ваш id: написать ему может кто угодно, но слушает он только вас.

## 5. Запустите

<!-- tutorial:run -->
```bash
cd ~/health-docker
docker compose up -d
docker compose ps
```

Первый запуск скачивает образ — несколько минут, на экране бегут строки загрузки. Ожидаются
четыре строки — `bot`, `cron`, `dashboard`, `lab-intake` — в колонке STATUS `Up …`. Первые
секунды у `cron` может стоять `health: starting`: он создаёт пустую базу, а остальные ждут его.
База и журналы живут в томах Докера: обновление образа их не трогает.

## 6. Проверьте, что всё живо

Через пару минут после старта:

<!-- tutorial:run -->
```bash
cd ~/health-docker
docker compose exec -T cron python3 -c "import daemon_liveness as d; print(d.find_down_daemons())"
```

`[]` — все постоянные службы отмечаются. Сразу после старта там может стоять «пульса нет ни
разу» — подождите минуту и повторите. Та же строка у `bot` и через пять минут значит, что бот
не поднялся; причина — в его журнале:

```bash
docker compose exec -T cron sh -c 'tail -n 20 /app/logs/bot_err.log'
```

Чаще всего там `InvalidToken` — неверный токен в шаге 4. Исправьте файл той же строкой `printf`
из шага 4 (в `~/health-docker/secrets`), затем из `~/health-docker` перезапустите бота:
`docker compose restart bot`.

Проверка показывает `[]`, а бот молчит — почти наверняка неверный id: бот не отвечает чужим.
Сверьте `cat ~/health-docker/secrets/telegram_chat_id` с ответом `@userinfobot`.

Дашборд — страницы в браузере, где видно то, что система о вас знает: медкарта, анализы,
гипотезы, задачи. Откройте на этой машине `http://127.0.0.1:8001`. Пока вы не прошли знакомство с
ботом, страницы почти пустые — это нормально. Дашборд без пароля, поэтому открыт только на
этой машине.

## 7. Включите автозапуск

Контейнеры сами поднимаются, когда работает Докер. На Маке нужно, чтобы после перезагрузки
поднималась и Colima. Для этого есть агент — скачайте его и включите:

```bash
curl -fsSL https://github.com/larrynovsky/larry-health-os/releases/latest/download/com.larry.health.colima.plist \
  | sed "s#__HOME__#$HOME#g" > ~/Library/LaunchAgents/com.larry.health.colima.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.larry.health.colima.plist
```

Проверьте: `launchctl print gui/$(id -u)/com.larry.health.colima | head -3` печатает описание
агента. Если `bootstrap` при повторе ответил `5: Input/output error`, агент уже загружен — это
нормально.

Агент стартует при входе в вашу учётную запись. После отключения света Мак включится, но
система поднимется только когда кто-то войдёт в систему. На Linux Docker Engine стартует сам,
если включён: `sudo systemctl enable docker`.

## 8. Познакомьтесь с ботом

Напишите своему боту в Telegram:

```
/start
```

Бот предложит короткое знакомство, около десяти минут. Первый вопрос — «Язык / Language?»:
выберите «Русский» или «English». Следом он спросит, как к вам обращаться. Отвечайте текстом
или кнопками. После каждого ответа бот показывает записанное — так видно, что он понял
правильно. Если понял не так, пройдите знакомство заново командой `/about`.

В конце бот покажет сводку того, что теперь знает, и через пару минут пришлёт первый утренний
отчёт. Проблемы со здоровьем, о которых вы рассказали, придут отдельными карточками с кнопками
«✅ Применить» и «✖ Отклонить»: только применённая попадёт в ваш список проблем. Отчёт не пришёл
за десять минут — посмотрите журнал бота (команда из шага 6): чаще всего там ключ Anthropic
или пустой баланс.

Под карточкой бот попросит документы: заключения врачей, выписки и анализы за последние три
года (PDF или фото) и сырые данные генома, если вы делали генетический тест. Присылайте их
файлами прямо в чат. На каждый файл бот ответит, что с ним сделает. Диагнозы и лекарства из
заключений придут карточками — в медкарту попадёт только то, что вы подтвердите. Геном грузится
в фоне, об окончании бот напишет отдельно. Подходят сырые данные 23andMe, AncestryDNA,
MyHeritage, FTDNA, tellmeGen и LivingDNA, а также полный геном в VCF (разбор идёт часами).

Распознавание документов знает английский и русский. Документы на другом языке требуют своей
сборки образа — см. [«Как поставить систему в Докере»](../how-to/install_docker.md)
([English](../how-to/install_docker.en.md)).

Файл больше 20 МБ Telegram боту не отдаёт — тогда пришлите ссылку на него в Google Drive:
[«Как прислать боту большой файл»](../how-to/send_large_file.md)
([English](../how-to/send_large_file.en.md)).

Бот молчит на `/start` — смотрите шаг 6.

## Что нормально видеть в первые дни

- В журналах — «пороги лаб-трендов не посеяны: нет снимка EFLM» и «лаб-пороги safety_net не
  посеяны». Справочники EFLM и CTCAE не входят в образ по лицензии; система работает на
  встроенном резерве.
- «Нет действующего Google Calendar токена» — календарь не подключён; это необязательно.
- В ночной проверке — «данных нет» и «не судимо в контейнере»: установка пустая, а часть
  проверок относится к разработке, а не к работе системы.

## Как обновиться

Когда вышла новая версия, скачайте её `compose.yaml` — в нём имя нового образа — и поднимите
контейнеры заново:

```bash
cd ~/health-docker
curl -fsSL -o compose.yaml https://github.com/larrynovsky/larry-health-os/releases/latest/download/compose.yaml
docker compose up -d
```

`up -d` скачивает новый образ и пересоздаёт только те контейнеры, у которых он сменился; база,
ключи и ваш `.env` с поясом остаются. Если в описании выпуска на GitHub сказано, что изменились
настройки, скачайте и `.env` (шаг 2) и заново укажите пояс (шаг 3).

## Windows через WSL2 (не проверено)

**Этот путь никто ещё не прошёл до конца.** Образ собран для Linux, а WSL2 — настоящий Linux
внутри Windows, поэтому он должен работать, но проверен он не был. Если вы его прошли — или
застряли — напишите в issues репозитория: это сделает путь проверенным.

1. Откройте PowerShell от имени администратора и поставьте Ubuntu:
   `wsl --install -d Ubuntu-24.04`. Перезагрузите компьютер, при первом входе в Ubuntu
   придумайте имя пользователя и пароль.
2. В окне Ubuntu поставьте Docker Engine и разрешите себе им пользоваться:

   ```bash
   curl -fsSL https://get.docker.com | sudo sh
   sudo usermod -aG docker $USER
   ```

   Закройте окно Ubuntu и откройте снова. `docker info --format '{{.ServerVersion}}'` должен
   напечатать номер версии. Docker Desktop для Windows не нужен.
3. Дальше — шаги 2–6 и 8 этого урока, все команды — в окне Ubuntu. Пояс для шага 3 —
   `timedatectl show -p Timezone --value`. Дашборд открывается в браузере Windows по тому же
   адресу `http://127.0.0.1:8001`.

Непроверенное место, о котором стоит знать заранее: Windows останавливает WSL, когда в нём
не открыто ни одного окна, — и вместе с ним всю систему. Держите окно Ubuntu открытым и
отключите сон Windows (Параметры → Система → Питание). Надёжного автозапуска для Windows
урок пока не даёт.

## Если что-то пошло не так

- **`bot` в состоянии `Restarting`** — шаг 6: журнал бота, чаще всего токен или id.
- **После перезагрузки Мака бот снова `Restarting`, а в журнале `Timed out` или
  `name resolution`** — виртуальная машина поднялась раньше сети и не находит имена сайтов.
  Остановите Colima, пропишите Докеру адрес DNS и запустите снова:

  ```bash
  colima stop --profile health
  sed -i '' 's/^docker: {}$/docker: {"dns": ["1.1.1.1"]}/' ~/.colima/health/colima.yaml
  grep '^docker:' ~/.colima/health/colima.yaml
  colima start --profile health
  ```

  `grep` должен показать строку с `1.1.1.1`. Показал `docker: {}` без изменений или что-то
  другое — впишите `"dns": ["1.1.1.1"]` в раздел `docker:` этого файла вручную.

- **`cron` перезапускается или не становится здоровым** — `docker compose logs cron`. Чаще всего
  неверный часовой пояс: исправьте его (шаг 3) и повторите `docker compose up -d`.
- **`docker compose up` отвечает `denied` или `not found` на образ** — проверьте имя образа
  (шаг 2) и сеть; образ скачивается из `ghcr.io`.

Подробности и случаи сложнее — в [«Как поставить систему в Докере»](../how-to/install_docker.md)
([English](../how-to/install_docker.en.md)).

## Чего урок не делает

- Не собирает образ из исходников. Это нужно для своих языков распознавания или своих правок
  кода — [«Как поставить систему в Докере»](../how-to/install_docker.md)
  ([English](../how-to/install_docker.en.md)).
- Не подключает дашборд к сети. Телефону он нужен для данных «Здоровья» — как открыть его в
  частной сети, но не в интернет, сказано в
  [«Как подключить „Здоровье“ iPhone»](../how-to/connect_apple_health.md)
  ([English](../how-to/connect_apple_health.en.md)).
- Не заводит второго человека в ту же установку.
- Не ставит вторую машину для разработки —
  [«Как добавить вторую машину для разработки»](../how-to/two_machine_setup.md)
  ([English](../how-to/two_machine_setup.en.md)).
- Не прогоняет тесты: они для тех, кто меняет код, и идут вне контейнера —
  [«Как запускать тесты»](../how-to/run_tests.md) ([English](../how-to/run_tests.en.md)).
