# Как подключить тонометр Withings

> **Тип документа:** How-to (Diátaxis). Шаги 1–4 — для **исходной установки автора** (клон
> репозитория, Python 3.11 на машине). Для **установки из образа Докера** шаг 1 тот же, а шаги 2–4 —
> в последнем разделе.

Зачем: давление тонометра Withings приходит к системе через «Здоровье» iPhone, а этот путь
теряет замеры молча. Прямое подключение к Withings даёт второй, независимый источник: каждый
замер со своим временем и пульсом. Он ложится в таблицу `bp_readings`, а ночная проверка
сравнивает его с тем, что пришло через «Здоровье».

Подключение разрешает системе только **чтение измерений** (`user.metrics`): давление, пульс,
вес. Записывать в Withings система ничего не может.

Что нужно: аккаунт Withings, в котором видны замеры тонометра; браузер, где вы можете войти
в этот аккаунт; терминал на компьютере **с этим же браузером**.

## 1. Создайте приложение в портале разработчиков Withings

1. Откройте [портал разработчиков](https://developer.withings.com/dashboard/) и войдите
   своим аккаунтом Withings. На вопрос о дата-центре выберите тот, где ваш аккаунт
   (для Европы — Europe Cloud).
2. Портал попросит организацию: **Create organization** → любое название (например,
   `Health OS personal`) и свой email → **Next**.
3. **1. Application creation:** отметьте **Public API integration**. Прочтите условия
   (**Terms of use**) и отметьте **I accept the terms of use** → **Next**.
4. **2. Information:**
   - **Target environment** — оставьте **Development**.
   - **Application name** — например, `Health OS BP import`.
   - **Application description** — например, `Personal import of my own blood pressure readings`.
   - **Registered URLs** — ровно `http://localhost:9877/withings/callback`.
5. Нажмите **Done**. Появится жёлтое предупреждение: адреса `http` и `localhost` не годятся
   для боевого режима, приложение ограничено 10 пользователями. **Это ожидаемо:** для себя и
   своей семьи этого хватает. Нажмите **Done** ещё раз.
6. Откроется окно с **Client ID** и **Client Secret**. Секрет показывается **один раз** —
   не закрывайте окно, пока не выполните шаг 2. Секрет не отправляйте боту или в чат.

## 2. Сохраните Client ID и Client Secret

Скопируйте в окне портала **Client ID** и сразу в терминале выполните:

```bash
mkdir -p ~/.health_secrets && chmod 700 ~/.health_secrets
pbpaste | tr -d '[:space:]' > ~/.health_secrets/withings_client_id && chmod 600 ~/.health_secrets/withings_client_id
```

Затем скопируйте **Client Secret** и выполните:

```bash
pbpaste | tr -d '[:space:]' > ~/.health_secrets/withings_client_secret && chmod 600 ~/.health_secrets/withings_client_secret
printf '' | pbcopy   # очистить буфер обмена от секрета
```

Проверка без показа значений: `wc -c ~/.health_secrets/withings_client_*` — у каждого файла
64 символа (так было у владельца 05.10.2026). Теперь окно портала можно закрыть.

`pbpaste`/`pbcopy` — команды macOS. На Linux вместо них `xclip -o -selection clipboard`
и `xclip -selection clipboard < /dev/null`.

## 3. Разрешите доступ один раз

```bash
cd ~/health_scripts && python3.11 withings_api.py
```

1. Терминал напечатает ссылку. Откройте её в браузере **на этом же компьютере**.
2. Войдите в Withings, проверьте, что аккаунт тот, где ваши замеры, нажмите **Allow**.
3. Браузер перейдёт на `localhost:9877` и покажет «Готово, окно можно закрыть.». Код из этого адреса
   живёт 30 секунд, поэтому его ловит сама команда — копировать ничего не нужно.
4. Дождитесь в терминале `Withings подключён; токен сохранён в …/withings_oauth.json (0600)`.
   Команда ждёт нажатия Allow 5 минут, потом останавливается — тогда запустите её заново.

**Если система работает на другой машине** (у автора — Mac Studio, а браузер на MacBook):
выполните шаги 2–3 на машине с браузером, но в отдельную временную папку, и перенесите три файла:

```bash
mkdir -p ~/.withings_setup && chmod 700 ~/.withings_setup
# шаг 2 — те же команды, но в ~/.withings_setup вместо ~/.health_secrets
cd ~/health_scripts && HEALTH_SECRETS_DIR=~/.withings_setup python3.11 withings_api.py ~/.withings_setup/withings_oauth.json
scp -p ~/.withings_setup/withings_client_id ~/.withings_setup/withings_client_secret \
       ~/.withings_setup/withings_oauth.json <машина-системы>:.health_secrets/
ssh <машина-системы> 'chmod 600 ~/.health_secrets/withings_*'
```

После переноса удалите временную папку: копия токена в ней станет недействительной при первом
же обновлении на машине системы, а секрет приложения лежать лишним экземпляром не должен.

Где что живёт дальше. `~/.health_secrets/withings_oauth.json` — первичная выдача; система её
только читает. Withings **меняет токен обновления при каждом обновлении**, поэтому живой токен
система пишет в каталог данных (`data/withings_oauth.json`, права 600) и сохраняет новый до
использования. Не копируйте старый файл токена поверх нового: старый токен обновления погашен.

## 4. Проверьте импорт

```bash
cd ~/health_scripts && python3.11 import_withings.py
```

Ожидаемо: `Withings: замеров давления N, удалено как удалённых в Withings 0, дней давления
пересчитано M`, код выхода 0. Каждый запуск забирает всю историю Withings и делает базу её
зеркалом: замер, удалённый вами в приложении как неудачный, удалится и здесь. Дневное давление
(среднее всех замеров дня) с подключением Withings пишет он, а не «Здоровье» — дни до первого
замера Withings остаются как были. Дальше импорт идёт по расписанию дважды в день, в 09:10 и 21:10.

Сверьте один замер с приложением Withings: в базе время хранится в UTC, в приложении — местное.

```bash
cd ~/health_scripts && python3.11 -c "
import health_db as db
with db.get_conn() as c:
    for r in c.execute(\"select datetime(measured_at,'unixepoch','localtime'), systolic, diastolic, pulse from bp_readings order by measured_at desc limit 3\"): print(*r)"
```

**Проверено 05.10.2026:** подключение владельца, затем импорт кодом этой версии в контейнере
основной машины на временной базе — получено 3 замера, время и значения совпадают с ответом
Withings (коды мер 9 — диастолическое, 10 — систолическое, 11 — пульс подтверждены живым ответом).
Сверка одного замера с приложением Withings владельцем — ещё предстоит.

Если Withings не подключён (нет файлов из шагов 2–3), импорт молча завершается с кодом 0 —
это не ошибка. Если подключён, но Withings отказал, импорт завершается с кодом 1 и
пишет сбой в журнал сбоев; его разбирает ночной цикл.

## Если не получилось

- **нет файла withings_client_id / пустой withings_client_secret** — шаг 2 не выполнен или файл
  пуст. Повторите шаг 2. Если окно с секретом уже закрыто, а секрет не сохранён, ищите
  выпуск нового секрета в настройках приложения в портале (этот путь здесь не проверен).
- **ответа от Withings не было за 5 минут или state не совпал** — Allow не нажали вовремя или
  открыли ссылку из прошлого запуска. Запустите шаг 3 заново и откройте новую ссылку.
- **Браузер пишет «не удаётся подключиться» к localhost:9877** — браузер на другом компьютере,
  чем команда, либо команда уже остановилась. Запустите шаг 3 на машине с браузером.
- **invalid redirect_uri** в Withings — адрес в портале не совпадает с
  `http://localhost:9877/withings/callback` буква в букву.
- **токен Withings нечитаем; авторизуйте заново** или отказ при обновлении — повторите шаг 3.
  Новая выдача свежее живого токена, и система возьмёт её.

## Установка из образа Докера

Шаг 1 (приложение в портале Withings) — тот же. Дальше, на компьютере, где работает Докер,
**и с браузером на этом же компьютере**:

**2Д. Ключи.** Сохраните в `Downloads` два файла простого текста: `withings_client_id` — только
Client ID, `withings_client_secret` — только Client Secret (как для Oura). Скопируйте их одной командой:

```bash
cd ~/health-docker && install -m 600 "$HOME/Downloads/withings_client_id" "$HOME/Downloads/withings_client_secret" secrets/
```

На Linux, если ваш UID не 1000, — та же команда `install` через `sudo` с ключами `-o 1000 -g 1000`.
Затем удалите обе копии из `Downloads`.

**3Д. Разрешение.** Приёмник кода запускается во временном контейнере, а порт 9877 пробрасывается
только на `localhost` этой машины:

```bash
cd ~/health-docker && docker compose run --rm -p 127.0.0.1:9877:9877 -e WITHINGS_CALLBACK_BIND=0.0.0.0 cron python3 withings_api.py /home/health/health/data/withings_oauth.json
```

Откройте напечатанную ссылку в браузере этого компьютера, нажмите **Allow**, дождитесь
`Withings подключён; токен сохранён в …`. Разрешение ложится в том данных (`data/withings_oauth.json`,
права 600), а не в `secrets`: каталог ключей в контейнере только для чтения. Если порт 9877 занят,
команда остановится с ошибкой — освободите порт; другой порт не годится, он записан в портале Withings.

**4Д. Проверка.**

```bash
cd ~/health-docker && docker compose exec -T cron python3 import_withings.py
```

**Проверено 06.10.2026 на образе основной машины, без настоящей учётки:** с `WITHINGS_CALLBACK_BIND=0.0.0.0`
и пробросом порта ответ браузера с верным `state` доходит до приёмника в контейнере («Готово, окно
можно закрыть.»), с чужим `state` — отказ; без переменной порт снаружи недоступен. Подключение
настоящей учётки этим путём ещё не проходило.
