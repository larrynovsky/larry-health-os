# Как поставить систему с ключом другого поставщика моделей

Урок [первой установки](../tutorials/first_install.md) ставит систему с ключом Anthropic — это
единственный путь, на котором работает всё. Этот рецепт — для тех, у кого есть ключ OpenAI или
Gemini и нет ключа Anthropic.

## Сначала посмотрите, что будет работать

Работает только та часть системы, чья модель прошла допуск у этого поставщика. Таблица —
[что работает на каком поставщике](../reference/llm_providers.md). Роль с «нет» или «не
проверялась» отказывает громко (ошибка `ModelNotAdmitted`), а не отвечает непроверенной
моделью. Пример: если у роли sonnet стоит «нет», распознавание анализов по фото не работает
(оно читает каждую страницу двумя разными моделями), а чат и чекин могут работать.

## Установка

Вместо `bash install.sh` из урока:

```bash
bash install.sh --provider openai
```

Скрипт спросит ключ OpenAI (ввод скрыт), проверит его у `api.openai.com` списком моделей
(это бесплатно) и положит в `secrets/openai_key`. Для Gemini — `--provider gemini`, ключ
проверяется у `generativelanguage.googleapis.com` и ложится в `secrets/gemini_key`.

Без вопросов (например, на сервере):

```bash
LLM_KEY=… HEALTH_TZ=Europe/Berlin TELEGRAM_TOKEN=… TELEGRAM_CHAT_ID=… \
  bash install.sh --provider gemini --non-interactive
```

В конце скрипт перечислит допущенные роли и напомнит, что остальное не работает.

## Сменить поставщика позже

Запустите установку ещё раз с другим `--provider`: строка `HEALTH_LLM_PROVIDER` в `.env`
поменяется, контейнеры пересоздадутся, база и ключи останутся. Повторный запуск без
`--provider` выбор не меняет.

## Что важно знать

- Все тексты и документы, которые система отправляет модели (анализы, выписки, чат), уходят
  выбранному поставщику. Его условия обработки данных — ваше решение.
- Счёт за модели — на вашем ключе у поставщика. Баланс скриптом не проверить: пополните его.
- Как система выбирает модель и что происходит, когда поставщик её отключает, —
  [объяснение](../explanation/model_choice.md).
